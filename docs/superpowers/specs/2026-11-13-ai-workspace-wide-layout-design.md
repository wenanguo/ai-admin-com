# 最大化后的 AI 工作台：一屏铺满 —— 设计

日期：2026-11-13
状态：待批准

## 一句话

最大化之后**不该还要滚**：对话区吃满剩余高度，「待确认/审计/规则」收进右侧窄栏，
意图卡片墙折进输入框上方的抽屉 —— 一屏看完，不滚。

## 现状（实测）

最大化的浮层盖住内容区（1536×894），但内容总高 **1598px** ⇒ 要滚。

从上到下：标题栏 → 模型条 → 对话区（固定 `min(560px, 55vh)`，实测 522px）→
待确认/审计/规则三个页签 → 意图卡片墙（10 张）。

四个具体问题：

1. **对话区不占满**：1536px 宽只给 522px 高，空对话时是一大块灰。
2. **要滚才看得到**：「待确认」（AI 写操作要人点头的地方）在对话区**下面**；
   意图卡片墙在最**底下** ⇒ 点一张意图卡片要先滚到底，填完还要滚回输入框
   （现在靠 `scrollIntoView` 兜）。
3. **模型条是给开发者看的**：整行写着
   「服务端没有模型列表端点，也没有配额端点 ⇒ 只显示当前模型；没有数据源就不画配额条」。
4. **「最大化」没兑现「一屏看全」**。

## 决定：布局 A（一屏铺满）

```
┌─────────────────────────────────────────────────────────────────┐
│ AI 工作台  命令层受控写入·实时引用        [历史对话][新对话][返回] │
├──────────────────────────────────────────────┬──────────────────┤
│ 对话区（flex:1，吃满剩余高度）                │ 右侧栏 360px     │
│ ┌──────────────────────────────────────────┐ │ ┌──────────────┐ │
│ │ 消息…（里面自己滚）                       │ │ │ 待确认 (2)   │ │
│ │                                          │ │ │ ──────────── │ │
│ │                                          │ │ │ 审计         │ │
│ │                                          │ │ │ ──────────── │ │
│ ├──────────────────────────────────────────┤ │ │ 规则与AI分工 │ │
│ │ [意图卡片 ⌃]                            │ │ │ (单栏堆叠)   │ │
│ │ 输入框…                        [发送]    │ │ └──────────────┘ │
│ └──────────────────────────────────────────┘ │                  │
└──────────────────────────────────────────────┴──────────────────┘
```

### 1. 宽版容器：整页不滚

- 根容器：`height:100%` + `display:flex; flexDirection:column` + **`overflow:hidden`**
  （现在是 `overflowY:auto` ⇒ 内容一高就出滚动条）。
- 中间一行：`display:flex; gap`；左边 `flex:1; minWidth:0`；右边 `width:360px; flexShrink:0`。
- 头部、模型条、对话区、右侧栏**各自固定高**，多出来的全给对话区。

### 2. 对话区（`WideChat`）：高度改成吃满

- 去掉 `height: 'min(560px, 55vh)'` ⇒ 改成外层 `flex:1; minHeight:0`。
  里面的消息列表已经是 `flex:1; minHeight:0; overflowY:auto` ⇒ **滚动条只在消息区里**。
- 兜底 `minHeight: 320px`（路由页宿主的高度链若塌了，对话区不会缩成一条）。

### 3. 意图卡片墙 → 输入框上方的抽屉

- 输入框上方一排按钮：`[意图卡片（10） ⌃]`。
- 点开 ⇒ 一块**浮在对话区上方**的浮层（absolute，不占高度）⇒ 对话区仍然吃满。
- 点卡片 ⇒ 填输入框 + **自动收起抽屉**（不再需要 `scrollIntoView` 去找输入框）。
- 抽屉内容仍是 `IntentGallery`（含那句「点一下只填输入框，不自动发送」的说明）。

### 4. 右侧栏 = 待确认 / 审计 / 规则与 AI 的分工

- 三个页签从「对话区下面」挪到右侧栏（`Tabs` 竖排? 不 —— 页签仍横排，只是容器变窄）。
- **「规则与 AI 的分工」原本是双栏**（规则引擎 / LLM 并排）⇒ 360px 放不下 ⇒ 改成**单栏堆叠**。
- 面板吃满右侧栏高度，内部自己滚。
- 待确认/审计**按需读**的规矩不变（页签没打开不读接口）。

### 5. 模型条做减法

- 那一整行解释 ⇒ 收成一行短的：`模型 minimax-cn/MiniMax-M3.1-Flash` + `ⓘ` Tooltip 放原解释。
- 省下一整行高度。

### 6. 顺带改一处文案

- 输入区上方「（去「待确认」页签点头）」⇒ 右侧栏就在旁边 ⇒ 改成「（在右侧「待确认」里点头）」。

## 窄屏怎么办

最大化浮层的宽度 = **内容区宽度**（手机上是 ~400px）⇒ 360px 的右栏会把对话挤没。

⇒ **内容区宽度 < 900px 时，右侧栏改成从右边滑出的抽屉**（覆盖式），对话区占满宽度。

## 两个宿主都受益

`AiWorkspaceWide` 是最大化浮层与路由页 `/ai/workspace` **共用**的 ⇒ 改一处两边都变。
（窄版 400px 浮层**不动** —— 这次的诉求只针对最大化的界面。）

## 风险

- **路由页的高度链**：`/ai/workspace` 的宿主是 ProLayout 的内容区，
  若它的 `height` 不是确定值，`flex:1` 会塌 ⇒ 实现时要在路由页宿主上补
  `height:100%`（或 `minHeight`），并在浏览器里实测。

## 不做什么

- 不动窄版（400px 浮层）的界面。
- 不动后端 / AI 服务的任何契约。
- 不改对话的发送、流式输出、会话逻辑 —— **只改布局**。
- 不给右侧栏做「可折叠」：最大化的意义就是不滚，折叠等于把问题还回去。

## 守卫

- e2e：最大化后**页面本身不出现滚动条**（`scrollHeight <= clientHeight`）——
  这条直接钉住「一屏看全」。
- e2e：「意图卡片」按钮能展开抽屉，点卡片后输入框被填上、抽屉自动收起。
- e2e：右侧栏存在，「待确认」页签可切换。
- 现有 e2e（最大化覆盖内容区、返回不刷新原页面、窄宽切换不新建会话）**必须继续绿**。
