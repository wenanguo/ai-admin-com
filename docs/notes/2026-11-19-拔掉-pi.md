## 短设计（issue 说「中」⇒ 几段话）

| 决定 | 为什么 | 代价 / 取舍 |
| ---- | ------ | ----------- |
| **事件词汇我们自己声明**（`core/session/agent-event.ts`） | 以前内核每一层都 import pi 的 `AgentSessionEvent` ⇒ 换宿主要改一整条链 | 形状照抄 pi 的 ⇒ 迁移只是换类型名，不是重写 |
| **闸门决策与宿主无关**（`core/gate/decision.ts`） | 以前决策住在 pi 的 `tool_call` hook 里 ⇒ 拔 pi 会连它一起删 ⇒ 口径会丢 | dsh 的审批接线改成调用它（口径只有一份） |
| **工具类型自己声明**（`core/tools/types.ts`） | 同上（`AgentToolResult` / `ToolAnnotations` 都是 pi 的） | 适配层负责翻译成宿主的形状 |
| **运行时只剩一个执行层**（去掉 `AI_RUNNER` 双跑开关） | 「不留双份实现」 | 不能再一键切回 pi（**pi 已经没了**） |
| **派活用 dsh 的 headless 模式**（`dsh --profile dispatch "<任务>"`） | spec §2.8 的结论：`dsh-subagent-dsh-sdk` 是 `pi-launcher.js` 的同构替代；headless 是它的等价形态 | 派活需要一个 **dsh profile**（首次要 `pnpm add` 我们的插件 ⇒ 几秒） |
| **模型走我们自己的 provider**（`backend/ai/dsh-plugin`） | D5=A：我们不依赖 pi-ai | 派活要配 `DISPATCH_API_KEY`（过渡期可从 pi 的 `auth.json` 借**凭据**） |
| **pi-ai 用 npm `overrides` 顶掉**（`stubs/dsh-llm-pi-ai/`） | dsh 的底座默认挂着「pi-ai 支撑的 provider 适配器」⇒ **pi-ai 会进依赖树** | 那个适配器本来就是**休眠**的 ⇒ 换成空壳**行为不变**；但它必须在**每个 dsh profile** 里被关掉（`disabled: true`） |

## ⚠️ 语义变化（PM 要知道）

1. **上下文连续性换了机制**：pi 时代是把 DB 历史还原成 pi entries（`session-entries.ts`）；
   现在**由 dsh 自己的会话日志负责**（会话 id = dsh 的 session id ⇒ dsh 按同一个 id 恢复会话；
   映射落在 `ai_conversation.dsh_session_id`）。
   ⇒ **DSH_HOME 被清掉 ⇒ 模型会失忆**（前端仍看得到历史，因为历史在 `ai_message` 表里）。
2. **技能目录不再回落项目目录**：`buildDshSystemPrompt` 改成「**给了空数组 ⇒ 一个技能都没有**」
   （与 pi 路径一致 ⇒ 不跨智能体串味）。
3. **闸门的「拒绝原因」不再发给模型**：dsh 的审批只有 `rejected` ⇒ 人话原因留在界面/审计里。

## 决策记录（★ 最值钱的部分）

| 决定 | 为什么 | 错了的代价 |
| ---- | ------ | ---------- |
| **事件词汇自己声明，而不是照抄 pi 的类型** | 内核**不该**长在任何一个 SDK 上 | 照抄 ⇒ 每换一个宿主就要改一整条链 |
| **闸门决策抽成独立模块** | 口径（「新增放行、修改要点头」）是**产品语义**，不是宿主语义 | 不抽 ⇒ 拔 pi 时口径跟着删 ⇒ 静默失去审批 |
| **用 `overrides` 把 dsh 的 pi-ai 适配器顶成空壳** | 验收标准是「`npm ls` 两个都空」⇒ 光「不用它」不够 | 不顶 ⇒ pi-ai 仍在树里 ⇒ 验收不过（而且它随时可能被误用） |
| **派活用 headless 而不是 ACP / 子代理工具** | ACP 要实现协议客户端；子代理工具要父会话编排 ⇒ **改动最小**的是 headless（一个进程跑一个任务） | 将来要「多轮追问 / 并行派活」⇒ 再换 ACP |
| **派活的模型走我们自己的 provider** | D5=A（不依赖 pi-ai）⇒ 与产品同一条 provider 代码 | 走 dsh 官方的 pi-ai 适配器 ⇒ pi-ai 又进依赖树 |
| **保留 `.pi/`（提示词与技能）与 `~/.pi/agent/auth.json` 的**凭据**借用** | `.pi/` 是我们的**开发资产**（与 AI 服务依赖 pi 是两件事）；凭据过渡期不挪 ⇒ 派活流程不变 | 一起删 ⇒ 开发 agent 没了提示词、派活要重新配 key |

## 坑与提醒

- **npm 的 `overrides` + `file:` 依赖**：要用 **`$包名` 引用根依赖**的写法
  （`"@deepseek-ai/dsh-llm-pi-ai": "$@ai-admin/dsh-stub"`）⇒ 直接写 `file:./…`
  会被解析到**依赖方**的目录 ⇒ 装不上（且 `npm ci` 会报「lock 不同步」）。
- **dsh 的 profile 里那行 `llm-pi-ai` 要显式关掉**（`disabled: true`）
  ⇒ 否则 dsh 会警告「1 entry did not activate」（profile 里解析不到那个包）。
- **`npm install` 会重跑 prisma 的 postinstall** ⇒ 装完记得 `npx prisma generate`（否则类型报 `InputJsonValue` 不存在）。
- **Windows 上 `.cmd` 只能经 shell 起** ⇒ 派活器里 `pnpm add` 用 `shell: true` + 一条命令串。
- **dsh 的 headless 只在任务结束时输出** ⇒ 中途看进度只能看 git（工作区改动 + 最近提交）。
- **别删 `backend/ai/stubs/dsh-llm-pi-ai/`** ⇒ 删了 pi-ai 就又进依赖树了。
