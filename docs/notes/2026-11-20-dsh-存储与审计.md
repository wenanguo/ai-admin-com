## 目标

把**会话持久化与审计**迁到 dsh 的形状，同时**保住我们已有的数据与查询**。

## 状态

**代码完成，等人 review**（PR 未合并）。

## 结论（先看这个）

| 问题 | 结论 |
| ---- | ---- |
| 会话持久化用 `dsh-storage` 还是我们自己的表？ | **都不是（不是二选一）**：产品事实仍在我们自己的表，**执行痕迹**用 dsh 形状的**追加式事件日志**（新增表 `ai_session_event`，落在同一个 MySQL） |
| 和 `ai_conversation` 怎么共存？ | **并存**：`ai_conversation` 继续是「会话是什么」的事实源；新增**映射列** `ai_conversation.dsh_session_id`（**可空** ⇒ 旧会话照读） |
| 审计 | `ai_audit_log` **语义一字不改**；**补三类留痕**（模型调用 / 工具调用 / 闸门决策）⇒ 现有 `/api/audit` 查得到 |
| 对外契约 | `core/routes/contract.ts` **一字不改**；前端**零改动**（快照端点只**多**一个字段） |

## 决策记录（★ 最值钱的部分）

| 决定 | 为什么 | 错了的代价 |
| ---- | ------ | ---------- |
| **并存**（关系型行 + 追加式事件日志），**不选** `dsh-storage` | `dsh-storage` 家族是给**非会话的应用数据**用的 ⇒ 不是 `ai_*` 表的替代品；而且 `dsh-session-persistence-sqlite` 没有 0.2.2-rc.5（还在 0.0.1-rc.1 线）⇒ 强行用会引入第二条依赖线 | 二选一 ⇒ 前端要的「会话 + 消息」形状没了 ⇒ 前端要改 |
| **事件日志落在 MySQL**（而不是只靠 `dshHome` 的 JSONL） | 容器本地磁盘随容器一起没 ⇒ 进库才留得住；SQL 能查、能和审计表一起看 | 只留 JSONL ⇒ 容器一重建，「上周那轮调了哪些工具」就查不到了 |
| **新列可空、不回填** | 共享库上回填 = 多一次写操作（风险）；可空 ⇒ 旧会话**照读** | NOT NULL ⇒ 迁移得先回填全部旧会话 |
| **`ai_audit_log` 语义一个字不改**，只**补**三类留痕 | 「审计 = 谁做了什么、改前改后」的语义是产品承诺 ⇒ 改了等于换产品 | 改成「什么都往审计里塞」⇒ 审计页被噪音淹没，写操作审计反而看不见 |
| **工具调用「没有写审计才补」** | 写工具自己已经写了一条**更全**的写审计（带写前 / 写后快照）⇒ 再补一条就是同一件事记两遍 | 无脑补 ⇒ 审计页出现两条同名行 ⇒ 看着像重复 |
| **去重靠「留痕带」而不是「猜工具名」** | 内核不许知道业务命令名（业务词检查会红）⇒ 用「这次调用期间有没有写过这个命令的审计」判断 | 猜工具名（`create_` / `update_` 前缀）⇒ 内核绑死业务 ⇒ 复用不了 |
| **快照端点只「多」一个字段**（不改已有字段） | 契约表一个字都不用改 ⇒ 前端零改动 ⇒ 不用改前端就能上线 | 改 `messages` 的数据来源 ⇒ 契约变了 ⇒ 前端要跟着改 |
| **留痕失败不许影响对话** | 表还没迁移 / 库连不上 ⇒ 聊天不能挂 | 留痕一失败整轮失败 ⇒ 用户侧「AI 坏了」 |
| **迁移脚本不在库里执行**（只提交脚本） | 共享库 / 生产库上动手 = 高风险操作 ⇒ 由人在**测试库**先验（与 #81 的做法一致） | 我在生产库上 deploy ⇒ 出事没法回退 |

## 坑与提醒

- ⚠️ **审计页会多出 `model_call` 与只读工具调用的行** ⇒ 条目变多（**数据变多，不是契约变**）
  ⇒ PM 需要知道这个产品影响。
- ⚠️ **迁移前的老会话不保证能续聊**（issue 只要求「至少能读」）⇒ 那是 pi runner 下产生的会话。
- ⚠️ **dsh 侧自己那份 JSONL 仍在 `dshHome`** ⇒ 我们那张表是**可查询的投影**，不是替代品。
- ⚠️ `prisma generate` 在 Windows 上偶尔 **EPERM**（引擎 DLL 被占用）⇒ 类型已经更新了（报错只是 DLL 换名失败）⇒ 重试即可。
- ⚠️ **共享库上只能 `migrate deploy`** ⇒ `migrate dev` / `reset` 会 `DROP DATABASE aipm`。
- ⚠️ **worktree 的 `node_modules` 是指向主 checkout 的 junction** ⇒ 在 worktree 里 `npm install` 会改到主 checkout 的依赖树（本次已装上 `@deepseek-ai/*`，`package-lock.json` 没变）。
