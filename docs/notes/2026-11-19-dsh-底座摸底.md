## 八问结论速查（细节在 spec §2）

| 问 | 结论 |
| -- | ---- |
| 模型 | **成**：`deepseek-official` 路由 + 模型 id 直通 ⇒ `AI_MODEL=deepseek-official/deepseek-v4-flash` |
| MiniMax | **成，≈ 0 工作量**：dsh 自带 `dsh-llm-pi-ai` 适配器；自写 provider ≈ 1.5–3 人日 |
| 工具 | **成**，但 typebox ⇒ dsh 的 JSON-Schema 风格 DSL 要转一层（≈ 80 行） |
| 事件/流式 | **契约能保住**（前端零改动），但逐 token 会退化成**成批到达** |
| 审批 | **成**：`approval/request` ⇒ `allowed-once / rejected / cancelled`；没人应答 ⇒ fail closed |
| MCP | **成**：没有 `dsh-mcp`，但有 `dsh-mcp-client` / `-manager` / `-resources`（spike 实挂并被调用） |
| 存储 | **形状不同**：dsh 是追加式事件日志，我们是关系型行 ⇒ 两边都要，各管各的 |
| 子代理 | **成**：`dsh-subagent-dsh-sdk`（每个任务一个独立 dsh 子进程）= 今天 `pi-launcher.js` 的同构替代 |

## 决策记录（★ 最值钱的部分）

| 决定 | 为什么 | 错了的代价 |
| ---- | ------ | ---------- |
| **架构选「子进程 + stdio JSON-RPC」**（不是进程内嵌入） | 类型零外泄 + 故障隔离（dsh 是 RC）+ 升级只换子进程 | 逐 token 流式没了（D1）⇒ 若前端不接受，得改成进程内嵌入，类型边界要重画 |
| **锁 `0.2.2-rc.5` 全家桶**（不是 issue 里写的 `0.0.1-rc.1` / `agent 0.1.0-rc.6`） | 那两个是 npm 的 `latest` 标签，来自**两条不同的发布线** ⇒ 一起装**直接失败**（实测 ERESOLVE）；`0.2.2-rc.5` = 官方仓 master 2026-11-18，peer 图自洽 | 锁错线 ⇒ `npm i` 装不上，spike 跑不起来 |
| **版本全部精确写死**（无 `^` / `~`） | dsh 是 RC，`^` 会在某天悄悄换掉 ⇒ 我们的适配层会突然编译不过 | 升级不显式 ⇒ 出事时不知道是哪版引起的 |
| **升级单独一条 issue** | 「顺手升」是 RC 阶段最贵的习惯 | 一次功能 PR 夹带升级 ⇒ 出问题分不清是功能还是版本 |
| **spike 用 pnpm 独立沙盒**（不进 `backend/ai/package.json`） | dsh 的 profile/plugin 机制本身就是 pnpm；把 dsh 塞进 AI 服务依赖 ⇒ 升级 dsh 就等于升级我们的运行时 | 合并 ⇒ #120 的「换骨架」变成「换依赖树」，爆炸半径失控 |
| **闸门先按「工具自己问」设计** | `tools/pre-execute` 的统一拦截点实测**没触发**（根作用域插件） | 押注统一拦截点 ⇒ 闸门不生效 ⇒ **修改类操作直接放行**（安全事故） |
| **工具名必须归一化**（`mcp__aiadmin__create_task` ⇒ `create_task`） | 前端 `CommandCard` 直接显示 `toolName` ⇒ 不归一化就是**产品可见的变化** | 忘了 ⇒ 界面上冒出一堆 `mcp__aiadmin__xxx` |
| **MCP 先用 `dsh-mcp-client`，兜底自己写客户端** | 标准 MCP 协议（dsh 用官方 `@modelcontextprotocol/client`）⇒ 兜底成本低（≈ 1 人日） | 直接自写 ⇒ 白丢 dsh 生态的连接管理/重连/on-demand 加载 |

## 坑与提醒

- **npm 的 `latest` 在 dsh 上是坏的**：`dsh-agent` 的 latest 是 0.1.0-rc.6，其余是 0.0.1-rc.1
  ⇒ 混着装直接 ERESOLVE。**永远显式写版本。**
- **dsh 的 patch 语法**：改已有条目 `- id: <已有 id>`；**加**新插件 `- insert: [ { id, name, config } ]`
  ⇒ 写成 `- id: 新名字` 会被 loader 拒（`patch: entry "xxx" not found`）。
- **插件必须能被 profile 解析到** ⇒ 我们自己的插件要先 `pnpm add file:<路径>` 进 profile，
  否则**静默不加载**（工具表里就是没有它，很容易误判成「模型不听话」）。
- **pnpm 11 的供应链策略**会拦「刚发布不到一天」的 rc 包 ⇒ spike 的 `pnpm-workspace.yaml` 里
  显式 `minimumReleaseAge: 0`（版本已精确锁死，不是装最新的）。
- **Windows 上 `.cmd` 只能经 shell 起**（Node 的安全限制）⇒ spike 脚本里用一条命令串 + 引号。
- **abort 没有协议对应**：SDK 协议只有 initialize/prompt/query/resume/wait/working-directory/shutdown
  ⇒ 我们的 `POST /api/agent/:cid/abort` 需要单独方案（D2）。
- **dsh 的会话持久化有 sqlite 后端但没有 0.2.2-rc.5**（还在 0.0.1-rc.1 线）⇒ 本轮只走 JSONL。
