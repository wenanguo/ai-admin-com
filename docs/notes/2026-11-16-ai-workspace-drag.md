## 决策记录（★ 最值钱的部分）

| 决定 | 为什么 | 错了的代价 |
| ---- | ------ | ---------- |
| 配置存 `aipm.workspace` 的 `panel` 字段（不是新键） | 面板开合/页签/会话都在这一个对象里 ⇒ 几何也该在 ⇒ 只有一个键要管 | 新开一个键 ⇒ 两处存储逻辑、清理时容易漏 |
| **默认形态一个字不改**（右边 400px、顶到上下沿） | issue 明确「不改默认尺寸与默认位置」⇒ 没拖过时走老样式（`right:0; bottom:0`） | 改默认值 ⇒ 所有人一升级界面就变了 |
| 拖**标题** ⇒ 面板变成「浮动窗口」（高 560px） | 占满整屏高的面板**上下拖不动**（top 只能是 0）⇒ 「可拖到视口内任意位置」就不成立 ⇒ 拖动时必须给它一个小于视口的高度 | 不改高度 ⇒ 上下拖动永远没反应 ⇒ 验收标准「任意位置」不达标 |
| 调宽时**右边缘钉住**，只改宽度 | 拖的是左边缘 ⇒ 右边不动是「西侧缩放」的常规手感；面板默认贴右边 ⇒ 往左拖就是变宽 | 两边一起动 ⇒ 拖左边缘面板会乱跑 |
| 宽度上限 = **内容区宽**（不含左侧菜单） | issue 的验收标准；面板不许宽到盖住菜单那一列 | 用视口宽 ⇒ 面板能盖住菜单 ⇒ 导航没了 |
| 几何**从真实盒子量**（`getBoundingClientRect`），不是从 `window.innerWidth` 算 | 滚动条/缩放/边框会让「算出来的」和「画出来的」差几像素 ⇒ 每拖一次误差累积 | 用算的 ⇒ 拖几次后面板会飘 |
| 面板加 `box-sizing: border-box` | 边框（左边那条 1px）算在宽度里 ⇒ **存下来的宽度 = 渲染出来的宽度** | 不加 ⇒ 每次拖动差 1px（这个坑真踩过：521 ≠ 520） |
| 拖动监听器**当场挂上**（不等 React effect） | 挂在 effect 里 ⇒ 拖动的第一帧可能丢（真实浏览器里几乎看不出来，但单测会红） | 挂 effect ⇒ 「按下→立刻移动」的快速操作会丢第一帧 |
| **窄屏（手机）形态不允许拖** | 那个形态是「占满整宽」的手机界面，拖它没有意义（issue 明确） | 也能拖 ⇒ 手机上误触就把界面拖乱 |
| 宽版（最大化）**不拖** | issue 范围只说窄版 | —— |
| 拖动区域 = **标题文字**，不是整条标题栏 | 标题栏右边有「历史对话」「关闭」两个按钮 ⇒ 整条当拖动区会抢按钮的点击 | 整条当拖动区 ⇒ 点「关闭」会变成拖面板 ⇒ 关不掉 |

## 怎么验

```bash
cd frontend
npm run lint          # biome + tsc
npm test              # vitest（浏览器模式）
npm run build         # ⚠️ e2e 跑的是 dist/ ⇒ 改完源码必须先 build
npx playwright test e2e/ai-workspace.spec.ts
```

人眼要看的：

1. 任意页面点右下角机器人 ⇒ 浮层出现（还是右边 400px）；
2. 拖**左边缘** ⇒ 宽度变（最小 320，不会宽过内容区）；
3. 拖**标题「AI 工作台」** ⇒ 面板能被拖到视口任意位置（高度会变成一个窗口，不再占满整屏）；
4. 刷新 ⇒ 位置与宽度还在；
5. 点「最大化」再「返回」⇒ 位置与宽度**不丢**；
6. 拖动时页面**不会选中一片字**。

## 坑与提醒

- ⚠️ **拖标题会让面板从「占满整屏高」变成「560px 高的窗口」** ⇒ 这是有意的
  （不然上下拖不动），但用户第一次拖会觉得「怎么变矮了」。
- ⚠️ `frontend/e2e` 跑的是 **`dist/`（生产构建）** ⇒ 改完源码不 `npm run build` ⇒ 测的是旧代码。
- ⚠️ 单测在 **vitest 浏览器模式**下跑 ⇒ 用 `PointerEvent` 合成指针事件即可（不是 jsdom）。
- ⚠️ 拖动把手有 6px 宽 ⇒ 从把手**中间**起拖，实际宽度会差 3px（e2e 断言留了余量）。
- ⚠️ 存的是**视口坐标** ⇒ 换了个分辨率/屏幕大小，面板会被夹回视口内（不会跑到屏幕外找不着）。
