## 决策记录（★ 最值钱的部分）

| 决定 | 为什么 | 错了的代价 |
| ---- | ------ | ---------- |
| **AiAdmin 后端 = 外部实例**（不进 compose），用 `AIADMIN_PROXY_TARGET` 指向 | issue 要求「决定并写明」；AiAdmin 自己有一套 compose + 外部 MySQL/Redis ⇒ 拉进来要处理一整套依赖 | 编排变成「三套 compose 套娃」，且要改 AiAdmin 那个仓（超出本条边界） |
| **nginx 的 server 块改成 envsubst 模板**（`docker/web/templates/default.conf.template`），上游地址用环境变量注入 | 上游要能在「本地起 AiAdmin」与「线上外部域名」之间切换 ⇒ 写死在 nginx.conf 里就得**重构建镜像** | 改一个地址要重新构建 + 重新发布前端镜像 ⇒ 部署流程多一步且容易漏 |
| **`/api/` 的 `proxy_pass` 不带 URI 部分**；**`/ai-api/` 的带 `/`** | nginx 语义：`proxy_pass` 带 URI ⇒ 会把**匹配到的 location 前缀**替换掉 ⇒ `/api/` 的前缀被吃掉 ⇒ AiAdmin 404；`/ai-api/` 正是要**去掉**前缀 ⇒ 带 `/` 刚好 | 前缀被吃掉 ⇒ 业务接口 404（而且只在联调时才发现） |
| **两个名字很像的变量：`AIADMIN_PROXY_TARGET`（nginx 上游，**站点根**）与 `AIADMIN_BASE_URL`（AI 服务自己调 AiAdmin，**含 `/api/v1`**）** | 前者的 baseURL 已含 `/api/v1` ⇒ nginx 不能 rewrite；后者是 AI 服务出站用的 base ⇒ 必须含 | 混用 ⇒ 要么 AiAdmin 404，要么 AI 服务打到错误路径 |
| **AI 服务端口只绑 `127.0.0.1`**（`127.0.0.1:${AI_PORT}:3100`） | issue 的安全边界：公网唯一入口是 nginx 的 80 | AI 服务裸奔在公网 ⇒ 绕过 nginx（鉴权/限流/日志全丢） |
| **AI 服务用 `depends_on: ai (service_healthy)`** | 前端起来时 AI 服务要能用；且 AI 的 `/health` **恒 200** ⇒ 依赖没配好也只是 `degraded`，不会反复重启 | 前端先起、后端还没好 ⇒ 首屏报错 |
| **验收用「AiAdmin 桩」（nginx 回显 `$request_uri`）** | 真 AiAdmin 是另一个仓的 FastAPI，CI 里跑不起来；而**路径有没有被改写**正是本条最该验的东西 ⇒ 桩能直接回显到达上游的原始路径 | 只能验「容器起来了」，验不出「路径被 rewrite 了」这种最典型的错 |
| **验收脚本自己写假值 env 文件（`--env-file`），不读 `docker/.env`** | 开发者的 `docker/.env` 里有真值 ⇒ 验收不该碰它；CI 也不能依赖它 | 验收会用到真 key/真库 ⇒ 污染环境、CI 不稳定 |
| **compose 里保留 `build:` 段** | 新克隆的机器 `docker compose up -d` 就能跑起来（不用先手工 build 两个镜像） | 新机器上手步骤多一步 |

## 怎么验

```bash
# ① 静态断言（**不需要 docker**，任何机器都能跑）
node scripts/e2e/compose.static.cjs
# 或
npm run e2e:compose:static

# ② 真起 compose（需要 docker；本机没 docker ⇒ 打印 SKIP 并退出 0）
node scripts/e2e/compose.cjs
# 或
npm run e2e:compose

# ③ 手搓也行
cp docker/.env.example docker/.env      # 填 DATABASE_URL / MINIMAX_CN_API_KEY
docker compose -f docker/docker-compose.yaml up -d --build
curl -s  http://127.0.0.1:8080/healthz
curl -s  http://127.0.0.1:8080/ai-api/health
docker compose -f docker/docker-compose.yaml down -v
```

`②` 覆盖的验收点：`compose config` 通过、两个容器都 healthy、`/` 是前端页面、`/healthz` 200、
`/api/v1/ping` 到达上游时**路径原样**、`/ai-api/health` 是 AI 服务的健康 JSON（前缀已去掉）、
`/ai-api/api/agent/:id/events` 能到 AI 服务、AI 端口只绑 `127.0.0.1`。

## 坑与提醒

- **本机没有 docker** ⇒ 容器级验收只能靠 CI（`.github/workflows/docker-compose.yml`）。
  改完 nginx/compose **必须看 CI 的 compose job**。
- **envsubst 占位符必须有默认值**（镜像里 `ENV AIADMIN_PROXY_TARGET=...` / `AI_UPSTREAM=...`）：
  变量未定义时 envsubst **不替换** ⇒ nginx 启动报 `unknown "XXX" variable` ⇒ 容器起不来。
  ⇒ 改模板时，新加的 `${...}` 一定要在 Dockerfile 里配 `ENV` 默认值。
- **`AI_UPSTREAM` 默认是 `127.0.0.1:3100`**（不是 `ai:3100`）⇒ 独立跑前端镜像时 nginx 也能解析并启动；
  compose 里再覆盖成 `ai:3100`。
- **AI 服务启动时强校验环境变量**（`MINIMAX_CN_API_KEY` / `AI_MODEL` / `AIADMIN_BASE_URL` / `DATABASE_URL` / `ALLOWED_ORIGINS`）
  ⇒ **缺一个就退出** ⇒ `docker/.env` 必须配齐；CI 用假值启动。
- **`ai_*` 表必须已经存在**：与业务表同库 ⇒ 只能 `migrate deploy`（`migrate dev/reset` 会 DROP 整个库）。
  本条**不做迁移** ⇒ 上线前人工确认。
- 拆成「主配置 + 模板」后，#38 的 `scripts/e2e/web-container.static.cjs` 的断言也跟着改了
  （server 块的断言改到模板上读）⇒ 改 nginx 配置时**两个静态脚本都要跑**。
