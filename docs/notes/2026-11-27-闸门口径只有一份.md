## 坑与提醒

- ⚠️ **减法清单守卫（#180）把 core 的行数锁死了** ⇒ **改 core 就要回写清单**
  ⇒ 而回写清单又会撞上「改了清单的 PR 不许改产品代码」⇒ **改 core 之前先想清楚**。
  ⇒ 本条就是因此**换了方案**（零 core 改动）。
- ⚠️ **插件是「拷贝」进 dsh profile 的**（`pnpm add file:<路径>`）⇒ 插件侧**永远 import 不到**我们的内核
  ⇒ 想「复用内核那份判定」只有两条路：**交回内核**（本条选的）或**把口径当数据送过去**（第一版 ⇒ 要动 core）。
- ⚠️ **内核本来就判两次**（`core/adapter/dsh/approvals.ts` 里再判一次 `requiresConfirmation`）
  ⇒ 插件问一句不会重复问人 ⇒ **只问一次**（人只看到一次待确认）。
- ⚠️ 守卫扫的是「**恰好等于**前缀」的字符串字面量（`"update_"`）**且剥掉注释**
  ⇒ 业务侧的工具全名（`"update_task"`）**不算** ⇒ 插件的业务规则（`pm-context.ts` 那些）不受影响。
- ⚠️ **插件里连注释都不写那几个前缀** ⇒ `grep -rn "update_"` 全仓只命中内核那两处
  （闸门 + 审计）⇒ 人肉验收也一眼看得出来。
