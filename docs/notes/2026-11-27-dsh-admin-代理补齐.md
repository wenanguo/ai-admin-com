## 决策记录（★ 最值钱的部分）

| 决定 | 为什么 | 错了的代价 |
| ---- | ------ | ---------- |
| **前缀 `/dsh-admin` 一路不剥**（前端不 rewrite、nginx `proxy_pass` **不带 URI 部分**、Express 挂载自己剥）| 剥了前缀 ⇒ AI 服务那条路由不命中 ⇒ iframe 空白 | 用户看到「管理面白屏」，但后端日志一切正常 ⇒ **极难定位** |
| **Host 一路保留**（前端 `changeOrigin: false`、nginx `Host $host`、AI 服务反代 `changeOrigin: false`）| dsh 的栅栏比对 **authority**（浏览器看到的 host[:port]）⇒ 改写成 127.0.0.1 ⇒ 每个 API 都 403 | 整页能出 HTML、但**所有接口 403** ⇒ 像「加载中转圈」 |
| **`AI_DSH_ADMIN_ENABLED` 缺省仍然关** | ① 缺省开 = 缺省起不来（多一个 dsh web 子进程 + home 未必可写）② 缺省开 = 缺省坏（trusted-host 必须等于浏览器看到的 authority ⇒ 缺省值必然不匹配）③ 管理面 = 插件市场 / 终端 / 文件 ⇒ 是**提权面** | 缺省开 ⇒ 每个部署都起一个 dsh 且大概率是坏的 ⇒ **「装上就有」= 「装上就是坏的」** |
| **授权只认 AiAdmin 的 `is_superuser === true`**（`admin-judge.ts` → `resolver.resolve(token)`）| 载荷没验签 ⇒ 解 JWT 就能伪造 `{"access":"admin"}` ⇒ 拿到 dsh 的完整管理 UI | 权限提升 ⇒ **不可接受**（这条 issue 明确点名不许） |
| **没注入判定器 ⇒ 503（fail closed）** | 判定器没注入 = 「不知道谁是管理员」⇒ 宁可不可用 | 缺安全边界 ⇒ 任何人都能进管理面 |
| **前端只改 `config/proxy.ts`** | issue 的硬要求（前端 0 业务改动）⇒ 验收脚本里有一条断言专门钉它 | 管理面长成第二套前端 ⇒ 重复造轮子（这正是要避免的） |
| **验收脚本用「假的 authority」**（`dsh-admin.e2e.test`，故意不是 127.0.0.1）| 只有 Host 被**改写**时才会露馅 ⇒ 用 127.0.0.1 当 authority 测不出「Host 丢没丢」 | 断言变绿但其实 Host 被改写了 ⇒ 生产上每个 API 403 |
| **CI 的 `ai-service` job 加 `fetch-depth: 0`** | 「前端只改了 proxy.ts」那条断言要拿得到基线分支（`origin/main`）⇒ 否则只能跳过 | 断言长期跳过 ⇒ 变成「没有断言」 |

## 坑与提醒

- ⚠️ **dsh web 没有 cookie 就回 401**（不是重定向！）⇒ 浏览器第一次加载 iframe 时
  **自己没有** dsh 的签名 cookie ⇒ 靠**服务启动时换好的那份**（`exchangeTokenForCookie` ⇒ 反代注入）
  ⇒ 验收脚本里那条「冷启动」断言就是钉这个的（改成「先换 cookie 再访问」就测不出来了）。
- ⚠️ **Express 挂载会剥 `req.url` 的前缀** ⇒ hpm v4 的 `pathFilter` 匹配的是**剥掉之后**的 url
  ⇒ 用 `app.use('/x', proxy)` + `pathFilter: '/x'` ⇒ **永远不匹配**（本脚本踩过 ⇒ 404）。
  umi 是 `app.use(fn)`（不按路径挂）⇒ 前缀匹配才成立 ⇒ 浏览器那层**照 umi 的挂法**。
- ⚠️ **umi 用的是 hpm v3**（`context` 参数，**前缀匹配**），backend/ai 里装的是 **v4**（`pathFilter`）
  ⇒ 语义一样、写法不同 ⇒ 脚本里用 v4 的写法，注释里写明差异。
- ⚠️ **`pathFilter` 与挂载路径不能同时用**：要么挂路径、要么挂 `pathFilter`（二者只留一个）。
- ⚠️ 前端那条规则的 target **必须是 `http://…`**（umi 会把它当 proxy target）。
  本次做成**可被环境变量覆盖**（`AI_SERVICE_TARGET`）⇒ 验收脚本能指到随机端口。
- ⚠️ **nginx 的 `proxy_pass` 带不带 URI 部分，语义完全不同**：
  `http://host;` ⇒ 原样透传；`http://host/;` ⇒ 把匹配到的前缀换成 `/`。
  `/ai-api/` **要带**（去前缀），`/dsh-admin` **不能带**（要保留）。
- ⚠️ **WS 升级**要 http 层的 `map $http_upgrade $connection_upgrade`（nginx）⇒ 没它就不转。
- ⚠️ dsh 的 `--trusted-host`：**不带端口的条目匹配任意端口** ⇒ 开发期写 `localhost` 也行。
- ⚠️ compose 里给的是**命名卷**（不是宿主机目录）⇒ 不用管路径/权限；`compose down -v` 会清掉。
- ⚠️ **docker 本机没装** ⇒ compose 的 YAML 只做了**解析校验**（`yaml` 包）+ 静态断言，
  **没跑过真的 `docker compose up`** ⇒ 合并前最好在有 docker 的机器上起一次。
