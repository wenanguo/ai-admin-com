## ⚠️ 修复轮：admin 判定（PR #147 → `fd7a6cf`）

### 问题

原来的缺省口径是**解 JWT 载荷**看 `access === 'admin'`：

```ts
if (claims["access"] === "admin") return true;   // ❌ 载荷没验签
```

⚠️ **JWT 载荷没验签** ⇒ 任何人自己编一个 `{"access":"admin"}` 就能通过判定
⇒ 拿到 dsh 的**完整管理 UI**（插件市场能装包 / 终端 / 文件）⇒ **权限提升**。

⚠️ **字段名也不对**：真后端的 admin 字段是 **`is_superuser`**
（`frontend/src/access.ts: canAdmin = Boolean(currentUser?.is_superuser)`）；
`access === 'admin'` 只是 **mock 的形状**。

### 改法（照仓里现成的件，没另发明）

| # | 做什么 | 落点 |
| -- | ------ | ---- |
| ① | **问 AiAdmin**：`AadminClient.get(CURRENT_USER_PATH, token)` ⇒ 判 `is_superuser === true`（也认 `isSuperuser`）| `plugins/pm/adapter/aadmin/admin-judge.ts`（新）+ `current-user.ts`（映射）|
| ② | **默认一律 fail closed**：没注入判定器 ⇒ 拒绝（503）；判定器报错 ⇒ 也拒（401 / 502）| `core/adapter/dsh-admin/proxy.ts` |
| ③ | **带缓存**：`CachedCurrentUserResolver`（按 token 指纹 · 5 分钟）⇒ iframe 每个资源不打一次 AiAdmin | `plugins/pm/index.ts`（与「当前用户」共用同一份缓存）|
| ④ | **补单测**：伪造 `access=admin` / `is_superuser=true` 的载荷（头 / cookie / 查询参数**三条路**）必须被拒 | `proxy.test.ts` + `admin-judge.test.ts` |
| ⑤ | **文件头注释 + PR 正文**里「⚠️ admin 判定不是安全边界」那段一并更新 | 本文件 + PR #147 |

### 判定链（现在）

```
浏览器 ──▶ /dsh-admin/** ──▶ 反代
                             │
                             ├─ ① 取 token（Authorization / ?access_token= / cookie）
                             ├─ ② 判 admin：
                             │     isAdmin(token) ──▶ 插件的判定器
                             │                              │
                             │                              └─▶ AadminClient.get(
                             │                                     /system/user/current/info, token)
                             │                                    ⇒ is_superuser === true ?
                             │                              （带缓存 · 同一 token 只问一次）
                             ├─ 不是 admin ⇒ 403（**进代理之前** ⇒ 根本没打到 dsh）
                             ├─ 没判定器   ⇒ 503（fail closed）
                             └─ 判定器报错 ⇒ 401（token 过期）/ 502（权威系统挂了）
```

⚠️ **403 / 503 / 502 都是「拒」** ⇒ 权威系统挂了 = 管理面不可用（**不是**「谁都能进」）。

## 决策记录（读得懂的部分）

| 决定 | 为什么 | 放弃了什么 |
| ---- | ------ | ---------- |
| **用官方 `web` profile**，不裁剪界面 | dsh 自带 56 个 client-ui ⇒ 自己拼 profile 是重复造轮子 | 「只嵌一部分 UI」 |
| **Express 挂载剥前缀**（`app.use('/dsh-admin', proxy)`） | Express 自己剥 ⇒ 代理里**不改路径**（少一处能错的地方） | 在代理里 `pathRewrite` |
| **`changeOrigin: false`**（保留 Host） | dsh 的栅栏会比对 authority ⇒ 改写成 127.0.0.1 ⇒ 每个 API 都 403 | 改 Host（省事但全挂） |
| **`cookiePathRewrite: '/dsh-admin/'`** | dsh 发的是 `Path=/` ⇒ 浏览器不会把它发回来 ⇒ 免登录失效 | 原样透传 |
| **代理侧缓存 dsh 的签名 cookie**（`on.proxyReq` 追加） | 浏览器**完全不用知道** dsh 的 token ⇒ 免登录 | 让用户自己登录 dsh |
| **admin 判定放在进代理之前** | 普通用户**根本不会打到** dsh（少一层泄露面） | 代理里判（拦不住流量） |
| **admin 判定 = 问 AiAdmin**（`is_superuser`） | 载荷没验签 ⇒ 解载荷 = **权限提升**；权威系统说了算 | ❗**解 JWT 载荷**（原来那套 ⇒ 已删） |
| **判定器注入，不在核心里造** | 内核不认识 AiAdmin ⇒ 走**插件 → 内核**的注入（`AiPlugin.adminJudge`） | 在内核里写 AiAdmin 调用（破坏内核纯净） |
| **没判定器 ⇒ 503（fail closed）** | 缺配置 = 缺**安全边界** ⇒ 宁可管理面不可用 | 「缺省放行」/「缺省解载荷」 |
| **判定器报错 ⇒ 401 / 502（都拒）** | 权威系统挂了 ≠ 该放行 | 「挂了就当 admin」 |
| **判定与「当前用户」共用一份缓存** | 同一 token 只问一次 AiAdmin（iframe 几十个资源）| 各问各的（打爆上游）|
| **共享一个 dsh 实例**（不做多实例 / 多用户） | 管理面本来就只给 admin ⇒ 「谁改的」记我们自己的审计 | 每个 admin 一个 dsh |
| **总开关缺省关**（`DSH_ADMIN_ENABLED=0`） | 管理面是**可选能力** ⇒ 不配就不起 dsh web、也没有那条路由 | 默认就起（拖慢启动、占内存） |
| **`instance.ts` 自己 spawn，不用 SDK 客户端** | SDK 客户端走 **stdio JSON-RPC**（会话那条线）⇒ 管理面要的是 **HTTP/WS 服务** | —— |
| **静态 e2e 钉「没有自造路由」+「没有解载荷」** | 这两种口径最危险的失效方式就是「**又长回来**」⇒ 用静态检查钉死 | 靠人盯 |

## 坑与提醒

- ⚠️ **admin 判定现在是权威判定**（问 AiAdmin）⇒ **不再是「提示性」判定**。
  ⚠️ **代价**：AiAdmin 挂了 ⇒ 管理面不可用（503 / 502）⇒ 这是**故意**的
  （fail closed）。⇒ 部署时得保证 AiAdmin 的 `AIADMIN_BASE_URL` 配对。
- ⚠️ **缓存 5 分钟**（内核的 `CachedCurrentUserResolver`）⇒
  **刚被降权的管理员，5 分钟内仍能进管理面**（降权 ⇒ 要等缓存过期）。
  ⇒ 要立刻生效 ⇒ 得有个「清缓存」的入口（**目前没有** ⇒ 记在下面的 Minor 里）。
- ⚠️ **iframe 白屏的风险**：dsh 的 HTML 若用**绝对路径**引静态资源（`/assets/…`），
  浏览器就会去我们根路径要 ⇒ 404 ⇒ 白屏。**没法在静态检查里发现** ⇒ 人工验第一步就看这个。
- ⚠️ **WS 升级路径没有自动化测试**（要起一个 WS 服务）⇒ 只做了人工接线
  （`server.on('upgrade', handler.upgrade)` ⇒ 前缀自己剥）。
- ⚠️ **前端构建在 worktree 里跑不起来**：`frontend/node_modules` 是**junction**
  ⇒ utoopack 解析不了 ⇒ `topojson-client` 报缺（**与本 PR 无关**，CI 里正常）。
- ⚠️ **AiAdmin（FastAPI）那个仓没动**：后端菜单里**没有**「AI 管理」这一条
  ⇒ 菜单项是**前端自己加的**（像「首页」那样）⇒ 将来后端补了菜单，会出现两条
  ⇒ 前端已做「已有就不加」的判断。
- ⚠️ **cookie 名不许带产品代号**：内核不认业务（`scripts/check-core-purity.cjs`
  会拦 `aipm` / `aiadmin`）⇒ cookie 叫 `admin_access_token`（前后端一致）。

### Minor（可延后）

- **没有「清 admin 判定缓存」的入口** ⇒ 降权后要等 5 分钟才生效。
- **判定器返回 `false` 与「判不出来」不可区分**（都是 403）⇒ 排障时看服务端日志。
- **`is_superuser` 之外的角色权限没接**（管理面只认超级管理员 ⇒ 与前端 `canAdmin` 一致）。
