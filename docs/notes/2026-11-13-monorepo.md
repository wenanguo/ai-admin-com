## 决策记录（★）

| 决定 | 为什么 | 错了的代价 |
| ---- | ------ | ---------- |
| **AiAdmin（FastAPI）不进仓** | 它是**另一个项目**，有自己的发布节奏与仓库 | 三个仓耦合 ⇒ 谁都动不了 |
| **历史用 `git subtree` 保留** | 两条独立历史线合进一个仓，log 里能看出哪段来自哪个仓 | 丢历史（不可恢复） |
| **项目级的东西留根**（`.github` `.husky` `.agents` `.claude` `.superpowers` `docs`） | 它们是**整仓**级的东西，不属于前端 | 子项目各留一份 ⇒ 改一处要改 N 处 |
| **`biome.json` 放仓库根**（不是 `frontend/`） | biome **向上找 git 根** ⇒ 放子目录会与 `--config-path` 冲突 | biome 报「nested root configuration」 |
| **husky / lint-staged / commitlint 用 `frontend/node_modules/.bin/`** | 根目录**没有** node_modules（两套依赖各装各的） | 每次提交都 hook 失败，提交被拦下 |
| **`.gitignore` 全部改成 `**/` 前缀** | 原来大量规则带前导斜杠（只对根目录生效）⇒ 搬家后 `frontend/dist-dev` 挡不住 | 构建产物被提交进仓 |
| **workflow 用 `defaults.run.working-directory: frontend`** | 一次性给所有 run 步骤加目录，比逐个 step 改省事且不易漏 | CI 在根目录跑 ⇒ 找不到 package.json |
| **`src/.umi` 搬家后要重建** | 生成的类型里含**旧绝对路径** ⇒ `tsc` 报「@umijs/max 没有导出 XXX」 | 前端类型全红 |
| **旧目录 `D:/project/ai-admin-ai` 删掉** | 内容已搬空、历史已并入 + 有兜底 tag | 留个空壳目录 ⇒ 让人以为还有第二份代码 |

## 坑与提醒

- **`D:/project/ai-admin-ai` 曾删不掉** ⇒ 是有进程的 cwd 在里面（我起的探针脚本）⇒
  杀进程再删；`ls` 看见空目录也说明内容已搬走。
- **根目录现在有 `package-lock.json`**（并行开发时加的）⇒ 根 `npm run test` 是**串行**跑两个仓。
- **子项目一多，「加一个子项目」的成本被放大**（CI/husky/biome/lint-staged/commitlint 各一处要改）
  ⇒ 以后加子项目建议先做「脚手架」把这几处自动化。
