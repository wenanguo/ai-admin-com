## 决策记录（★ 最值钱的部分）

| 决定 | 为什么 | 错了的代价 |
| ---- | ------ | ---------- |
| **只升 Node 运行时，依赖一个都不动**（lock 只差根包 engines 那一行） | 本条是「骨架换 dsh」的**前置** ⇒ 必须小、可回滚、可一眼看出没夹带升级 | 顺手升了 antd/umi/prisma ⇒ 出问题分不清是 Node 24 的锅还是依赖的锅 |
| **engines 定 `>=24.9.0`（不是 `>=24`）** | `@deepseek-ai/dsh` 的 engines 就是 `>=24.9.0` ⇒ 定低了就装不上 dsh（那条还得再改一遍） | 声明比实际宽 ⇒ 人在 Node 24.0 上 `npm i` 成功、装 dsh 时才炸 ⇒ 坑埋得深 |
| **CI 里额外钉 `npm@10.9.9`** | node 24 自带 **npm 11** ⇒ 它的「package.json 与 package-lock.json 必须同步」检查比 npm 10 严 ⇒ 可能把现有 lock 判成不同步 ⇒ `npm ci` EUSAGE（**本仓 Dockerfile 里早就因为同一个坑钉过 npm**）。钉住 ⇒ CI 装出的树与 lock、与镜像**完全一致** ⇒ 兑现「依赖树不因升 Node 而变」 | 不钉 ⇒ 某个 job 的 `npm ci` 在 node 24 上 EUSAGE（本地 npm 11 dry-run 是过的 ⇒ **本地看不出来**，只能 CI 暴露） |
| **镜像里继续钉 npm 10.9.9（没改）** | 镜像那条钉 npm 的决定与 node 版本无关（是 npm 10 生成的 lock ⇒ npm 11 更严）⇒ 只把注释里的 `node:22` 改成 `node:24` | 顺手把镜像的 npm 也升到 11 ⇒ 镜像与 CI 两棵树 ⇒ 排查变难 |
| **写一个静态断言脚本把基线钉死**（`scripts/e2e/node-version.static.cjs`） | 这次改动散在 **CI / engines / 镜像 / 文档** 四处 ⇒ 以后任何一处漂移（有人加 workflow 忘了改版本）症状都很怪 | 靠人记 ⇒ 下次加 workflow 时又写成 22 ⇒ dsh 那条在 CI 上又装不上 |
| **断言脚本里还查「依赖树没变」**（lock 与基线分支逐字段比对，只差 engines） | 本条最怕的是「夹带升依赖」⇒ 让机器查，而不是靠人自觉 | 只能靠 review 肉眼 ⇒ 夹带升级很难被发现 |
| **历史 plan/spec/note 里的 `node:22` 也一并改** | 它们描述的是**当前镜像长什么样**（不是历史决策本身）⇒ 留着会误导下一棒 | 留着 ⇒ 下一棒照着文档找 `node:22` ⇒ 以为镜像还是 22 |
| **不改 `docs/legacy/` 与 `docs/archive/`** | 那是**上游/历史归档**，不是本仓事实源（README 里已注明） | 改归档 ⇒ 篡改历史，收益为零 |

## 坑与提醒

- ⚠️ **本机是 Node v26** ⇒ 本地跑得通**不代表** node 24 跑得通 ⇒ **一切以 CI 为准**。
  本条在 node 26 下没暴露任何新问题（无 punycode / require-ESM 警告），但那只是「没看到」。
- ⚠️ **node 24 自带 npm 11** ⇒ 这是本条唯一真正的行为变化 ⇒ 已用「CI 钉 npm 10.9.9」兜住。
  ⇒ 下次有人加 workflow，**记得也钉 npm**（不然就是新的 EUSAGE 坑）。
- ⚠️ **`engines` 不是硬门槛**：npm 默认只**警告**（`EBADENGINE`），不拦 ⇒ 本机 Node 22 也能 `npm i` 成功
  ⇒ 靠 `engines` 拦不住人 ⇒ 文档里写清「本地要 Node ≥ 24.9.0」才是真门槛。
- ⚠️ **镜像 tag 变了**（`node:24-bookworm-slim`）：bookworm-slim 的 glibc 更老一点，但两个镜像都**不用 alpine**
  ⇒ 预编译二进制（prisma 引擎 / esbuild / utoopack 的 Rust 内核）仍是 glibc 版 ⇒ 不受影响。
  ⇒ 但**本条没有 docker 环境**（这台机器没装 docker）⇒ 镜像构建只能靠 CI 的 docker job 验。
- ⚠️ `backend/ai/package.json` 原本**没有** `engines` ⇒ 本条补上了（并在 lock 里同步）
  ⇒ 属于「声明同步」，不是「改依赖」。
- ⚠️ `frontend/src/.umi/` 是生成物（里面也有旧的 `>=22.0.0`）⇒ 不入库、不用管。
- ✅ **CI 已验过 node 24**（PR #130 全绿，含两个镜像的构建与容器验收）⇒ 「node 24 上 npm 11 会 EUSAGE」
  这个担心**没有发生**（CI 里钉了 npm 10.9.9）⇒ 但钉 npm 的决定**保留**（它是预防，不是多余的绕路）。
