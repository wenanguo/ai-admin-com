## 决策记录（★ 最值钱的部分）

| 决定 | 为什么 | 错了的代价 |
| ---- | ------ | ---------- |
| **技能目录用环境变量 `AI_DSH_SKILL_DIRS` 传**（不是写进 profile 配置） | profile 是**磁盘上的工程** ⇒ 写进配置就变成「所有会话共用一份技能目录」⇒ 环境变量天然**一个会话一份** ⇒ 不跨智能体串味 | 智能体 A 的技能漏进智能体 B 的会话（业务上最严重的一种 bug） |
| **profile 补丁里 `includeDefaultRoots: false`** | dsh 的默认根含 `<项目根>/.agents/skills`（**本仓自己的开发技能**：`antd` / `pro-upgrade`）与 `~/.agents/skills`（**开发者的私人技能**）⇒ 不关就混进业务会话 | 业务会话里冒出开发技能；开发者改私人技能会意外影响线上会话 |
| **不装 `dsh-skill-filesystem` 依赖，直接配 base profile 那条** | 那个 provider **本来就挂在 sdk profile 里** ⇒ 只需**改它的配置**（`customSkillDirs`）⇒ 我们不重复挂一个 provider ⇒ 代码更少 | 多一个 provider ⇒ 同名技能两份 ⇒ 目录里出现重复项 |
| **MCP 管理面挂在**我们这个作用域**（不是 root）** | dsh 的工具表**按作用域** ⇒ 注册在 root 的工具 agent **看不见**（"unknown tool"）⇒ 必须与 agent 同层 | 模型看不见 MCP 工具 ⇒「后端加接口，AI 侧不用改代码」这条主张破功 |
| **注册完**等状态离开 `connecting`** | 管理面挂客户端是**异步**的 ⇒ 不等 ⇒ 模型第一轮可能看不到 MCP 工具 | 偶发「模型这次没调工具」（**最难查的那种 bug**） |
| **保留 `core/skills/skill-catalog.ts`（最小的一份）** | dsh 的技能登记表住在**运行时进程**里 ⇒ 我们的 HTTP 层**问不到** ⇒ UI 的技能清单端点只能自己读文件 | UI 上「我写的技能生效了」看不到 ⇒ 业务同学没法自查 |
| **清单的发现规则与 dsh 逐条对齐**（只一层 / kebab-case / 必填字段 / 同名先来的赢） | 清单与模型看到的不一致 ⇒ **界面骗人** | 界面上列了三个技能，模型只看得见两个 ⇒ 排查半天的灵异事件 |
| **MCP 写操作的闸门留在 dsh 插件里**（`tools/pre-execute`） | MCP 工具是 **dsh 直接注册**的 ⇒ 不经过命令桥 ⇒ **不会有人问** ⇒ 等于绕过了「修改已有数据要点头」 | **写操作不用点头** ⇒ 闸门形同虚设（**最严重**） |
| **闸门只问 `mcp__*` 且裸名 `update_` / `patch_`** | 我们的命令在**工具内部**已经问过了 ⇒ 不许问两遍（否则界面出现两次待确认） | 用户要确认两次 ⇒ 体验崩 |
| **技能正文一个字不改**（`SKILL.md`） | 技能正文是**提示词** ⇒ 进模型上下文 ⇒ 走 git 评审 | 提示词悄悄变了 ⇒ 谁都不知道模型为什么变了行为 |

## 坑与提醒

- ⚠️ **dsh 的技能目录是「一层深」**：`skills/<名字>/SKILL.md` 或 `skills/<名字>.md`
  ⇒ **别再套一层目录**（我们以前的 loader 会递归 ⇒ 这里有行为差）。
- ⚠️ **技能名必须 kebab-case**（frontmatter 的 `name`）：不许大写 / 下划线 / `--`。
  ⚠️ **名字缺失 ⇒ 技能直接不生效**（以前会回落成目录名）。
- ⚠️ **dsh 不认旧的驼峰键**（`disableModelInvocation` / `modelInvocable` / `userInvocable`）
  ⇒ 用连字符版（`disable-model-invocation` / `user-invocable`）。
- ⚠️ **`skill` 工具只回正文**（不读附属文件）⇒ 技能正文里**别依赖** `references/` 之类。
- ⚠️ **profile 补丁里 `config:` 是「整块替换」不是深合并**
  ⇒ 改 `skill-filesystem` 的配置时**要把该有的字段都写全**。
- ⚠️ **dsh 的 `!!js` 表达式在 dsh 进程里求值** ⇒ `process.env.AI_DSH_SKILL_DIRS` 拿得到；
  但**别**把它写进我们的 `.env`（`DSH_*` 前缀被 dsh 占用 ⇒ 用 `AI_DSH_*`）。
- ⚠️ **`dsh-mcp-manager` 的条目要求写明 `toolCallTimeoutMs`**（没有默认值）
  ⇒ 我们的 builder 一定写上。
- ⚠️ **管理面不落盘**：服务器**只在内存里** ⇒ 每次会话重新挂（这是对的：token 每个用户不同）。
- ⚠️ **MCP 的工具名是 `mcp__<server>__<tool>`** ⇒ 技能正文里写的也是它 ⇒ **别改**。
