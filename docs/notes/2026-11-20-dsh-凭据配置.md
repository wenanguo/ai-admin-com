# dsh 的凭据配在哪（issue #123 收尾）

## 一句话

**写在 `backend/ai/.env`**（那个文件已被 gitignore）⇒ **服务与 PM 派活都用它**。

```bash
# backend/ai/.env
DEEPSEEK_API_KEY=sk-你的官方key
```

## 变量名的三套叫法（别搞混）

| 位置 | 读什么 | 说明 |
| ---- | ------ | ---- |
| **AI 服务**（`src/core/adapter/dsh/runner.ts`） | `DSH_BASE_URL`（缺省官方）· `DSH_MODEL`（`deepseek-chat`）· `DSH_PROVIDER`（`deepseek-direct`）· `DSH_API_KEY_ENV`（**key 放在哪个变量里**，缺省 `DEEPSEEK_API_KEY`） | `.env` 由 `src/core/env/load-env.ts` 加载 ⇒ **必须在 `backend/ai/` 下启动服务** |
| **dsh 子进程**（`dsh-plugin/src/index.js`） | `DSH_AI_PROVIDER` / `DSH_AI_MODEL` / `DSH_AI_BASE_URL` / `DSH_AI_API_KEY` | **由服务翻译过去**（`runner.ts` 拼好再 spawn）⇒ 人**不用**直接配这四个 |
| **PM 派活**（`scripts/agent/lib/dsh-dispatch.cjs`） | `DISPATCH_PROVIDER` / `DISPATCH_MODEL` / `DISPATCH_BASE_URL` / `DISPATCH_API_KEY`（`DISPATCH_API_KEY_ENV` 改名） | ⚠️ **也读 `backend/ai/.env`** ⇒ 一把 key 两处用 |

## 派活的路由怎么选

```
显式 DISPATCH_PROVIDER ⇒ 听它的（模型与地址**跟着**它变 ⇒ 不会配错）
否则有 DEEPSEEK_API_KEY ⇒ 官方（deepseek-direct / deepseek-chat / https://api.deepseek.com/v1）
否则有 MINIMAX_CN_API_KEY ⇒ minimax / MiniMax-M3.1-Flash / https://api.minimaxi.com/v1
```

## 两条规矩

1. **凭据只在内存里**：只进子进程的 `DSH_AI_API_KEY`（`buildChildEnv` 里有测试盯着）⇒ 不落盘、不进日志。
2. **派活彻底不碰 pi**：连 pi 的 `auth.json` 都不借了（issue #123 收尾）⇒ 没有 key 就**报清楚**，
   不猜、不偷用别的凭据。

## 怎么验

```bash
node scripts/e2e/dispatch-dsh.static.cjs   # pi 拔干净
node --test "scripts/agent/*.test.cjs"      # 路由/模型/地址配对 + 凭据不外泄
node scripts/agent/dispatch.cjs --issue <号> # 能起 dsh 子会话
```
