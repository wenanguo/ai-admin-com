## 决策记录（★ 最值钱的部分）

| 决定 | 为什么 | 错了的代价 |
| ---- | ------ | ---------- |
| **用户可配的变量一律 `AI_DSH_*`，旧的 `DSH_*` 不再读** | dsh 的 app-boot `BOOTSTRAP_PREFIXES` 含 `DSH_` ⇒ 任何 `.env`（包括 dsh 启动目录的那个 = `backend/ai/.env`）里出现 `DSH_*`，**dsh 直接拒绝启动** | 若为了「兼容」把旧的读回来 ⇒ 等于继续教人在 `.env` 里写 `DSH_*` ⇒ 用户一照做 dsh 就炸（这正是本次要修的真 bug） |
| **dsh 自己认的名字（`DSH_HOME` 等）不改，照原名进子进程环境** | 进程环境里 dsh 是允许的（它禁的只是 `.env` **文件**）；改了就 dsh 不认 | 改了 ⇒ dsh 找不到 home / 权限模式失效 |
| **插件侧 `DSH_AI_*` 也改 `AI_DSH_*`** | 同一个理由（万一被写进 `.env` 就炸）+ 免得跟 dsh 的命名空间混淆 | 不改 ⇒ 埋一颗同样会炸的雷 |
| **D3 脚本「没有 key 就跳过、exit 0」** | CI 里没有官方 key；验收要**真花钱**打官方 API ⇒ 只在本地/带 key 环境跑 | 改成「没 key 就失败」⇒ CI 永远红；改成「假模型」⇒ 就验不到官方路由了 |
| **工具目录照 PM 那版的 DSL 形状写** | dsh 的工具参数是 **DSL**（`{ tz: { type: "string", required: true } }`），不是 JSON Schema；写错会被 dsh **静默丢掉**（模型看不见那个工具） | 「顺手改成标准 schema」⇒ 模型永远不调工具 ⇒ 验收永远卡在「工具没被调用」上，且**没有报错**（最难查的一种） |
| **③ 的断言看「命令桥收到了」而不是「`execute` 被调到」** | dsh 侧执行工具时会**回调我们的服务**（`agentRuntime.executeDshCommand`），本脚本是独立进程、没起服务 ⇒ 用假命令桥接住 | 断言 `execute` ⇒ 永远 0 次（误报失败） |

## 坑与提醒

- ⚠️ **改插件读的变量名时，三处要一起改**：`runner.ts` 的 `buildChildEnv`、`dsh-plugin/src/*.js`、
  `scripts/agent/lib/dsh-dispatch.cjs`（派活器）。漏一处 ⇒ 服务端或派活链路静默没有 provider。
- ⚠️ **`.env.example` 里注释掉的示例也算**（`# DSH_MODEL=…` 就是在教人配）⇒ 守卫会拦。
  叙述性的注释（不带 `=`，比如「缺省 `<DSH_HOME>/dsh-admin`」）是允许的。
- ⚠️ 线上/本地已有的 `.env` 里如果写过 `DSH_*` ⇒ 要改成 `AI_DSH_*`（不改会**静默走缺省**）。
- ⚠️ `scripts/agent/merge-pr.test.cjs` 有一条 worktree 清理的测试在本工作区环境里会失败
  （`git worktree remove` 说「不是工作区」）—— 与本 PR 无关，是脚本对「已不存在的工作区」不幂等。
