# 00 · 主规格（Master Spec）

> 范围、目标、方案决策记录。**这是所有其他文档的源头**；细节在 01–07。

## 1. 定位

> **AIPM**：一个**对话驱动的项目管理平台**——用一句话完成项目/里程碑/任务/风险的全部日常操作，AI 同时基于平台数据给出可解释的进度预测与风险预警。

与上游 PRD-v2 的定位差异：PRD-v2 是"在 AiAdmin 上做企业级 PM 系统，AI 是增强层"；AIPM 是"**AI 是主操作入口，结构化视图是辅助**"。

## 2. 目标 / 非目标 / 反目标

### 目标
1. 用中文一句话完成：建任务、改截止日、改状态、拆里程碑、登记/升级风险、批量调整。
2. 每次 AI 操作都走统一的命令层，产生可读的"命令卡片"；批量与破坏性操作进入**待确认队列**。
3. 每次写操作都留审计记录，且**可撤销**。
4. 项目/里程碑/任务/风险有完整结构化模型与基础视图。
5. AI 洞察可用：延期预测、风险预警、周报，并能一键转成待执行命令。

### 非目标（第一版不做）
- 计费、多租户 SaaS 化、外部干系人门户、自定义工作流引擎、白板协同、移动 App、工时审批。
- 飞书机器人（架构预留，见 01 §3.12）。
- 甘特图、PMO 组合仪表盘、项目模板（v1.1）。

### 反目标（做到即失败）
- **AI 直连数据库**——由 LLM 拼出的 SQL 一律是缺陷。
- **静默的破坏性操作**——批量改、删除、风险升降级、拆分，无人确认即生效即缺陷。
- **不可回溯的 AI 变更**——每次 AI 写入都必须可查、可撤销。
- **规则被 LLM 覆盖**——进度、风险、健康度的**数字**必须由确定性规则算出，LLM 只负责措辞。
- **AI 不可用即系统不可用**——关掉 key，手动操作与全部视图必须照常。

## 3. 方案决策记录（不可静默推翻）

### 3.1 AI 在产品中的角色
| 方案 | 取舍 |
|---|---|
| A. AI 只做分析 | 实现最简，没解决"操作贵"的核心痛点 |
| B. AI 只做操作入口 | 操作极快，但人无法纵览状态，容易盲信 AI |
| **C. AI 做入口 + 洞察（采用）** | 实现量最大，唯一同时解决"操作快"和"看得清" |

### 3.2 交互载体
| 方案 | 取舍 |
|---|---|
| ① Web 内嵌面板 | 闭环最紧，但只在电脑前 |
| ② IM 机器人 | 手机随时可用，但上下文要靠 @项目界定 |
| **③ 两者都要（采用，分两步）** | 第一步做 ①，命令层与传输层解耦；第二步挂 ② |

### 3.3 AI 工作台的位置
| 方案 | 取舍 |
|---|---|
| 右侧抽屉 | 遮挡主内容，任务栏宽度不可控 |
| 左侧菜单内 | 与导航混在一起，层级混乱 |
| **常驻右侧栏（采用）** | 与左侧导航对称，主内容始终可见；可折叠（⌘B）让出全宽 |

### 3.4 系统形态
**两段式 + 后端两模块**（详见 01）：

```
① 前端界面 ──REST+SSE──▶ ② 后端 ┬ 模块① CRUD 业务代码（适配层）
                                └ 模块② Agent 代码（pi agent）
```

- **模块① 默认通路 = 转发外部已实现的 API**（不重复造数据层）；备选通路 = 直连数据库。
- **模块② 用 pi agent 实现**（`@earendil-works/pi-coding-agent` SDK）。

### 3.5 技术栈
Next.js (App Router) + TypeScript + PostgreSQL + Prisma + Tailwind/shadcn + pi agent + MiniMax。

### 3.6 模型供应商
**MiniMax**。接入方式与三条硬约束见 05 §4。

### 3.7 撤销语义
**补偿式撤销**——外部 API 无字段历史时，每次写前先 GET 存旧值，撤销 = 反向写入（01 §4.5）。

### 3.8 待确认机制
**pi extension_ui 桥**——工具挂起等待人答复，答复到达后**原地恢复**（01 §4.6）。

### 3.9 权限
两层简化：用户（邮箱+密码）+ 项目成员（VIEWER/MEMBER/ASSIGNEE/MANAGER/OWNER）。AI 相关权限 `ai:use` / `ai:admin` / `ai:audit` 以用户标记实现。

### 3.10 上游 PRD-v2 的吸收边界

| 层 | 处理 |
|---|---|
| 业务模型层（状态机、不变量、口径、矩阵、预测、评测） | **全量移植** → 02、04、05 |
| 框架层（AiAdmin 脚手架、代码生成器、RBAC 中间件） | **不移植**（仓库无 AiAdmin 代码） |
| 架构层（命令层、待确认、可撤销、常驻工作台） | AIPM 独有，保留 |

## 4. 指标（对齐 PRD-v2 §1.3，按 AIPM 口径裁剪）

| 维度 | 指标 | 目标 | 测量 |
|---|---|---|---|
| 效率 | 平均建任务耗时 | 5 min → 30 s | `nl_to_task` 端到端埋点 |
| 采纳 | AI 建议采纳率 | ≥ 55% | 采纳 / 编辑保存 / 拒绝 三按钮埋点 |
| 准确 | 里程碑达成日预测 MAPE | ≤ 25% | 离线评测集（30 个历史项目留一） |
| 风险 | AI 预警被处理比率 | ≥ 70% | `risk_accepted / risk_suggested` |
| 安全 | AI 写操作可回溯率 | **100%** | `AuditLog` 覆盖所有写命令（硬指标） |

埋点字段见 03 §6。

## 5. 验收标准（整体）

第一版算完成，当且仅当：

1. **一句话操作**：输入"把本周所有 P0 任务的截止日顺延到下周一" → 返回命中清单预览 → 确认后落库，日期由后端按 Asia/Shanghai 周一为起点解析。
2. **确认门槛**：风险降级、跨项目批量、删除、拆分均需确认；单条常规改动直接执行。
3. **可回溯**：每次写入都有 AuditLog；拆分与批量撤销后数据与操作前**完全一致**；冲突时拒绝静默覆盖。
4. **可解释的判定**：里程碑显示"有风险"时能说明依据；ETA 预测给出 P50/P90 与置信度。
5. **规则优先**：无 key 时健康度、风险识别、进度口径、燃尽图照常工作。
6. **AI 挂了系统不瘫**：关掉 key 后手动建任务、改状态、各视图、审计与撤销全部可用。
7. **人工与 AI 同路径**：手动拖拽看板同样产生 AuditLog 并可撤销。
8. **引用可回跳**：AI 的每条结论都能点回原始任务/里程碑/风险。
9. **断线不丢待确认**：刷新/断网重连后，未决的待确认卡片完整恢复（01 §4.7）。
