# 07 · 待确认问题

> 按"阻塞程度"排序。**🔴 阻塞开发** / 🟡 影响设计但不阻塞 / 🟢 可以后置。

## 🔴 阻塞

### Q1 · "外部已实现的 API"具体是哪一个？

**需要提供**：
- 接口文档或地址、鉴权方式（服务账号 / OAuth / token）
- 实体与字段：项目 / 里程碑 / 任务 / 风险 的字段名与**状态枚举**、**优先级枚举**
- 分页方式、错误码格式

**为什么阻塞**：适配层的字段映射（06 §4）、枚举归一、能力声明全部取决于它。模块① 的 P1 阶段无法开始。

**如果暂时拿不到**：按最保守假设设计——`supportsDelete=false`、`supportsBatchUpdate=false`、`supportsHistory=false`、无依赖图。撤销退化为纯补偿式，删除退化为本地逻辑删除。后续接入真实 API 时只改适配层实现。

### Q2 · 外部 API 是否支持这些能力？
逐项确认（对应 06 §3 的能力位）：

| 能力 | 影响 |
|---|---|
| **删除** | 不支持 → 撤销退化为本地"逻辑删除"，数据在外部仍在 |
| **批量更新** | 不支持 → 适配层循环 + 限流 + 部分失败报告；批量命令体验变差 |
| **历史版本 / ETag** | 不支持 → 撤销只能补偿式；支持则优先用它（更可靠） |
| **自定义字段** | 不支持 → `extra_fields`（标签、优先级补充）无处存 |
| **任务依赖** | 不支持 → 依赖图与 CPM 关键路径失效，ETA 预测降级为纯 burndown |
| **评论** | 不支持 → 评论功能隐藏 |
| **限流配额** | 决定批量操作的节流策略 |

### Q3 · 外部 API 的认证方式与凭据管理？
- 服务账号固定凭据 / OAuth 动态令牌 / 每用户令牌？
- 令牌过期怎么续期？续期失败对用户可见吗？
- 是**所有用户共用一个外部账号**，还是**每个用户映射到自己的外部账号**？

**为什么重要**：若是"每用户映射"，适配层需要用户身份透传，权限模型（02）与审计的 `actor_id` 都要跟着变。

## 🟡 影响设计

### Q4 · 第一版是否要真实多用户登录？
**建议：要**（邮箱+密码最简）。审计要能区分"谁改的"，撤销的冲突检测（INV-14）依赖"他人后续修改"这个概念。
若不要，冲突检测退化为"仅比较 `updated_at`"，且审计里所有人都是同一个 actor。

### Q5 · 里程碑 AT_RISK 的规则阈值
当前默认值（可参数化）：进度 < 50% 且剩余 < 14 天、速度比 < 0.8、阻塞 > 3 天、逾期 3 天 grace 期。
**这是产品判断**：阈值太松则满屏黄灯，太紧则没人看。

### Q6 · 风险等级的矩阵边界是否照搬？
当前用 `score = p × i`（p/i 各 1..5），≥16 严重 / 9-15 高 / 4-8 中 / <4 低。
原型里的示例（概率"中"×影响"高"显示为红色"高"）与这个矩阵不完全一致——需要确认以哪个为准。

### Q7 · 周起点与时区
当前：周起点 = 周一，时区 = Asia/Shanghai，区间闭区间。
影响"本周所有 P0 任务"这类说法的命中范围。

### Q8 · v1 是否做评论？
**建议做**（成本低、AI 总结价值高）。会议纪要放 v1.1。

### Q9 · 飞书机器人何时做？
架构已预留（`Conversation.channel = FEISHU`）。v1 不做。

### Q10 · 是否引入向量库做"相似项目"检索？
**建议 v1 不做**，用标签 + 历史速率相似度。PRD-v2 把 pgvector 放在 M3。
