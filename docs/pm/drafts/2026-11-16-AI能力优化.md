### Issue 1

#### 标题

`[agent] 窄版 AI 工作台补「历史对话」（宽版有、窄版没有）`

#### 正文

```markdown
## 目标

**窄版**（常驻右侧 400px 的小窗口）AI 工作台**没有「历史对话」** ⇒ 换话题后没法回看，
AI 显得「失忆」；而**宽版（最大化）是有历史对话的**。

⇒ 把宽版已有的那套历史对话能力，**补到窄版**，并且**两种形态共用同一份实现**。

## 验收标准

- [ ] 窄版能打开「历史对话」（入口与宽版一致的位置与交互）
- [ ] 列表来自 `listAiConversations()`；点一条能加载该会话的历史消息并**接着聊**
      （`getAiState`），而不是只显示一个标题列表
- [ ] **三态齐全**：加载中 / 空（还没有任何会话）/ 失败（有错误提示且可重试）
- [ ] **两种形态共用同一份实现**（不要把宽版那段抄一份到窄版）
- [ ] 窄版只有 400px 宽 ⇒ 列表项的标题/时间**不溢出**（该截断就截断）
- [ ] 打开历史对话**不打断正在进行的流式输出**（SSE 不受影响）
- [ ] 有测试钉住（单测：列表渲染 + 三态；e2e：打开→点一条→恢复）
- [ ] `npm run lint` + `npm run test` 绿；相关 e2e 绿

## 范围

- 要做：
  - 把宽版已有的历史对话实现**抽成可复用**的部分，窄版接上
  - 窄版的历史对话入口（按钮/抽屉）
- 不做：
  - ❌ 不做会话的删除/重命名/搜索（后端没这组接口）
  - ❌ 不改会话的存储与后端协议
  - ❌ 不动宽版的现有行为（只做共用化，不改它的交互）
  - ❌ 不动 AI 服务的端点
  - ❌ 不动 `backend/ai`

## 上下文

- **宽版已有、窄版没有**（本条的全部由来）：
  - `frontend/src/components/ai-workspace/AiWorkspaceWide.tsx:262-278`
    —— `handleHistoryOpen` ⇒ 打开时调 `listAiConversations()` ⇒ 拉会话列表
  - `frontend/src/components/ai-workspace/AiWorkspaceShell.tsx`
    —— **整个文件里没有一处 `conversation`** ⇒ 窄版没有这个能力
- 前端接口：`frontend/src/services/api/ai/client.ts`
  - `:80 listAiConversations()` · `:110 getAiState(conversationId)` · `:87 createAiConversation()`
- 后端**已经持久化**了会话与消息（所以数据一直都在，只是窄版看不到）：
  `backend/ai/prisma/schema.prisma:19` `ai_conversation` · `:36` `ai_message`
- **两种形态共用组件的现成例子**：`AiWorkspaceWide.tsx` 里的 `sidebar` 变量
  （同一个 React 元素，宿主换地方渲染它 ⇒ 行内 ↔ 抽屉的 portal）
  ⇒ 历史对话也该这么共用，而不是抄两遍
- 窄版的盒子样式在 `AiWorkspaceShell.tsx` 约 359-372 行（`position: fixed; top; right; bottom; width`）

## 依赖

无。**但排在「窄版可拖动」那条之前** —— 两条都动 `AiWorkspaceShell.tsx` ⇒ 串行，避免冲突。

## 约束

- [x] 不直落 main（走分支 + PR）
- [x] 改动要有测试
- [x] 端到端行为要有验收脚本（`scripts/e2e/`）
- [x] 涉及 `AiAdmin`（另一个仓）时，**在那边单独提 PR**，并在这里说明（本条**不涉及**）

## 规模

- [x] 小
- [ ] 中（加一个功能/改一个模块）—— 写短设计
- [ ] 大（架构改造/跨模块重构）—— 写 spec + plan

> PM 判断：归**中**——要把宽版实现抽成共用（要动宽版文件），不是纯新增。
```

### Issue 2

#### 标题

`[agent] 窄版 AI 工作台可拖动（宽度可调 + 位置可移动）`

#### 正文

```markdown
## 目标

窄版 AI 工作台现在**位置和宽度都是写死的**（`right: 0; width: 400px`）⇒ 不能按需调整。

⇒ 让它**可拖动**：拖左边缘调宽度、拖标题区移位置，并且**刷新后保留**。

⚠️ 这条是**人早就提过的需求**（2026-11-14 讨论「最大化顶到最上沿」时说的：
「**我希望后续这个界面可以拖动**」）—— 当时为了「先让它能占满上沿」铺路，先做了上沿对齐。

## 验收标准

- [ ] **拖左边缘能调宽度**：有最小宽度（不小于 320px）与最大宽度（不超过内容区宽）
- [ ] **拖标题区能移动**：可拖到视口内任意位置
- [ ] 拖动中**不误选中文本**（拖动期间禁用文本选择），松手后恢复
- [ ] **位置与宽度刷新后保留**（存 `localStorage`）
- [ ] 窄屏形态（当前会变成 100vw 全宽的那种）**不允许拖动**，仍按现有逻辑走全屏
- [ ] **最大化 ↔ 窄版来回切换时**，调整过的位置与宽度**不丢失**
- [ ] 拖动不破坏现有的遮罩层与 `z-index` 关系（窄版 `zIndex: 100`，宽版 101）
- [ ] 有测试钉住（至少：宽度持久化、切换不丢）
- [ ] `npm run lint` + `npm run test` 绿；相关 e2e 绿

## 范围

- 要做：
  - 窄版的拖动（调宽 + 移动）与持久化
  - 与「最大化 ↔ 窄版」切换的状态衔接
- 不做：
  - ❌ 不做宽版（最大化）的拖动
  - ❌ 不做「吸附到边缘」「记忆每个页面的位置」这类花活
  - ❌ 不改窄版的默认尺寸与默认位置（默认仍是右边 400px）
  - ❌ 不动 `backend/ai`

## 上下文

- 窄版盒子：`frontend/src/components/ai-workspace/AiWorkspaceShell.tsx` 约 359-372 行
  —— `position: fixed; top: headerHeight; right: 0; bottom: 0; width: narrow ? '100vw' : AI_WORKSPACE_WIDTH; zIndex: 100`
  ⇒ **现在没有任何 drag/resize 逻辑**（文件里只有 `window` 的 resize 监听，那是「测量」不是「拖动」）
- 常量 `AI_WORKSPACE_WIDTH`（默认 400px）
- 形态切换的 state：`wide`（`AiWorkspaceShell.tsx:134` `useState(false)`）⇒ 切到宽版时 `variant="wide"`
- 两种形态**共用同一个 `<AiWorkspace>` 实例**（切形态不卸载 ⇒ 会话/SSE 不断）
  ⇒ 位置/宽度这些「壳」的属性要放在**壳**这一层，不要放进会被重建的子组件里
- 相关：issue #59（窄版顶到视口最上沿）的交接文档
  `docs/notes/2026-11-14-ai-workspace-max-height.md`（含 z-index 与头部补丁的决策记录）

## 依赖

- [x] 涉及 `AiAdmin`（另一个仓）时，**在那边单独提 PR**，并在这里说明（本条**不涉及**）

## 规模

- [ ] 大（架构改造/跨模块重构）—— 写 spec + plan

> PM 判断：归**中**——拖动 + 持久化 + 与形态切换的状态衔接；交互细节多，但都在一个组件里。
```
