## 目标

CI 里有两个**随机失败**的测试，它们**随机卡住别人的 PR**（合并被 required check 挡住）：

## 为什么这件事值得单开一条

2026-11-16 一天内，它们**卡了我 3 次**：

| 时间 | 被卡的 PR | 症状 |
| ---- | --------- | ---- |

## 现状与根因方向（**要你去核实并写清真因**）

### ① `PermissionModal.test.tsx` —— 疑似「提交时序」竞争

失败的是这两个用例（`AssertionError: expected "vi.fn()" to be called at least once`）：

- `:281` 「关掉再打开,表单里还是角色的菜单(不会把菜单权限清空)」→ 断言 `expect(mocks.setRolePermission).toHaveBeenCalled()`
- `:323` 「同一个角色、但记录里的菜单变了 ⇒ 表单跟着重建(不提交旧菜单)」→ 同上

该文件共 8 个用例，**失败的这两个都是在「表单重建」之后立刻断言「提交被调用」** ⇒
**疑似**：表单重建的 effect 与提交之间存在异步窗口（提交发生在重建之前 ⇒ mock 没被调用）。
⚠️ 注意同文件 `:262` 那个用例的标题就叫「打开后**立刻**提交,提交的也是角色现有的菜单(中间没有异步窗口)」
⇒ 这类「立刻/中间没有异步窗口」的用例天然容易在 CI 慢机上翻车。

⇒ **要做的**：定位真因（是**实现的时序缺陷**，还是**测试缺等待**）——
**两者处理方式完全不同**，别用「加个 sleep」糊过去。

### ② `login.spec.ts` —— 依赖**线上后端**（大概率）

```ts
// 验证码图片是后端下发的 base64 data URL
await expect(page.locator('img[alt="点击刷新验证码"]')).toBeVisible();
```

前端跑在本地 preview（`playwright.config.ts:19` `baseURL: http://localhost:8010`，
`webServer` = `npm run preview:e2e`），但**验证码是后端下发的** ⇒ 这个用例**依赖真实后端**
⇒ 线上抖动 / 证书 / 验证码服务慢 ⇒ 随机失败。

⇒ **要做的**：让它**不再依赖线上后端**。仓库里**已有现成的做法**：
`frontend/e2e/helpers.ts:295` 用 `page.route('**/api/v1/system/user/current/info', ...)` 拦截接口，
`frontend/e2e/ai-workspace.spec.ts:129` 的 `setupAiService` 也是同一套路 ⇒ 照抄这个模式即可。
