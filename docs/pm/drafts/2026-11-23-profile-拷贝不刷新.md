# 草稿 · 新 bug：dsh profile 里的插件**拷贝永不刷新** ⇒ 插件改动不生效

## 现象（2026-11-23 实测撞到）

派活时 dsh 直接报：

```
dsh: NO_ADAPTER: no adapter registered for provider "minimax"
```

⇒ 根因：**profile 里装的是我们插件的一份「拷贝」**（`pnpm add file:<我们的路径>` ⇒ pnpm 把它拷进去）
⇒ 而 `core/adapter/dsh/profile.ts` 的 `ensureDshProfile` 里有一句「**依赖已经是这个路径 ⇒ 直接跳过**」
⇒ ⇒ **profile 永远拿着旧拷贝** ⇒ 我们改了插件（这次是把 `DSH_AI_*` 改名成 `AI_DSH_*`）
⇒ ⇒ profile 里的旧拷贝读不到新变量名 ⇒ provider 压根没注册 ⇒ **派活直接瘫**。

## 影响

- **开发流程**：插件一改，派活就瘫（要手动删 profile 才能恢复）。
- **生产更严重**：容器里 profile 放在卷上 ⇒ **镜像升级后插件永远不更新** ⇒ 改了插件等于没改。

## 要做

1. `ensureDshProfile` **每次都刷新**那份拷贝（而不是「路径没变就跳过」）
   —— 具体做法自定（重跑 `pnpm add file:…` / 先删旧拷贝再装 / 用内容哈希当版本号），但**必须让「插件改了 ⇒ 立刻生效」**。
2. **加测试**：改一次插件内容 ⇒ 跑 `ensureDshProfile` ⇒ profile 里的内容**跟着变**（别只测「装得上」）。
3. 文档/notes 记一笔（这个坑很容易再踩）。
