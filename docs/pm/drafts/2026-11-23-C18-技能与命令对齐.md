# 草稿 · C18「技能与命令对齐」（等拍板）

> **为什么改口径**：roadmap 上 C18 记的是「skills 有 `list-tasks`/`update-task`，但 tools 只有 `create_task`」
> ⇒ 那是 **2026-11-16 的旧账**。**实测（2026-11-23）：AiAdmin 的 MCP 现在暴露 5 个工具**
> ⇒ `get_task_detail` · `list_tasks` · `create_task` · `update_task` · `patch_task_status`
> ⇒ **技能承诺的工具全都存在** ✓ ⇒ 旧缺口已自然消失。
> ⇒ 但**实测挖出三个新问题**（更真、更细）。

## 实测事实

| 事实 | 怎么验的 |
| ---- | -------- |
| AiAdmin MCP 暴露 **5 个工具**：`get_task_detail` `list_tasks` `create_task` `update_task` `patch_task_status` | 直接对 `AIADMIN_MCP_URL` 做 MCP 握手 + `tools/list` |
| **白名单按裸名匹配** ⇒ `mcp__aiadmin__create_task` 与我们自研的 `create_task` **是同一个名字** | `core/mcp/tool-names.ts` 的 `bareToolName()` 剥掉 `mcp__<server>__` 前缀 |
| ⇒ ⇒ **两个都放行、语义相反**：我们的用**领域名**（`project_key`/`type`/`status`/`priority`），MCP 的用**后端字段名**（`project_id`/`type_code`/`status_code`/`priority_code`） | `plugins/pm/tools/create-task.ts` 的文件头注释 + MCP 的 inputSchema |
| 技能正文写的是 **MCP 那套**（`mcp__aiadmin__*` + 后端字段名） | `backend/ai/.pi/skills/*/SKILL.md` |
| ⇒ ⇒ **我们自研的 `create_task` 事实上没人调**（模型按技能走 MCP 那个） | 同上 |
| `patch_task_status`（批量改状态）**没有任何技能** | `.pi/skills/` 只有 create-task / list-tasks / update-task |

## 清单（四项）

### C18-1 消除「同名两义」：删掉我们自研的 `create_task` 命令

- 理由：模型按技能走的是 **MCP 那个** ⇒ 我们自研的**没有消费者** ⇒ 与 #153「减法」同逻辑（**别造第二套**）。
- 要动：`plugins/pm/tools/create-task.ts`（删）+ `plugins/pm/index.ts`（注销）+ 相关测试 + **审计里的脱敏引用**（`core/audit/audit-redact.ts` 提到它）⇒ 一并清。
- ⚠️ **白名单 `tools: [create_task]` 保留**（它指的是 **MCP 的**裸名）⇒ **语义要写清**（注释说明「这是 MCP 的裸名」）。
- ⚠️ **提示词**（`agents/pm/prompt.md`：「建任务用 create_task」）要跟着改口径（提示词是资产 ⇒ 走 git 评审）。
- 验收：**同一个工具名只有一种语义**；白名单仍放行 MCP 的 `create_task`；有测试钉住「裸名匹配不产生歧义」。

### C18-2 技能正文与 MCP **真实 schema** 逐条对齐

- `list-tasks`：核「`page_size` 单页上限 100」的真实值、核状态码/优先级的**真实字典**（技能写「小写字典码 + 大写 P」⇒ 要核）。
- `create-task` / `update-task`：核必填字段与措辞（`update_task` 是**全量 PUT** ⇒ MCP 描述与技能一致 ✓）。
- ⚠️ **技能正文是提示词 ⇒ 进模型上下文 ⇒ 走 git 评审** ⇒ 改动要在 PR 里逐条说明「为什么改」。
- 验收：技能里写的每个参数名/取值都能在 MCP 的 inputSchema 里找到；有一条测试/脚本比对「技能提到的工具 ⊆ MCP 工具快照」。

### C18-3 给 `patch_task_status` 补一个技能

- 它能**批量改状态**（`ids` + `status`）⇒ 模型不知道它 ⇒ 只会逐条 `update_task`（PUT 必填字段多 ⇒ 极易漏 ⇒ 422）。
- 验收：技能存在且被某个智能体领用；正文说清「批量 vs 逐条」的取舍。

### C18-4 把「MCP 工具清单」做成**入库快照 + 守卫**

- 现状：技能里的 `mcp__aiadmin__*` 是**硬写的** ⇒ AiAdmin 改了工具 ⇒ 技能悄悄失配 ⇒ **没人知道**。
- 做法：把工具清单**快照**进仓（含抓取方法与更新时间）⇒ 守卫比对「技能提到的工具 ⊆ 快照」⇒ 失配就红。
- ⚠️ 守卫**不许联网**（CI 里没有 AiAdmin）⇒ 所以靠**快照**（要有「怎么更新快照」的说明）。
- 验收：守卫进 CI；改快照里的工具名 ⇒ 守卫红。

## 不做

- ❌ **不改 AiAdmin 仓**（它的 MCP 工具清单是事实源 ⇒ 我们只做快照与守卫）
- ❌ 不改对外 9 个端点 · 不动闸门口径 · 不改 dsh 版本
- ❌ 不给普通业务命令「补齐」到技能里（那是 AiAdmin MCP 的活 ⇒ 「后端加接口，AI 侧不用改代码」这条主张不许破）

## 规模

中（4 项，但每一项都不大；**关键是口径对齐，不是加功能**）
