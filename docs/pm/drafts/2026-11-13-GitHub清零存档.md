- **关闭**：2026-11-13T08:34:12Z

```markdown
## 现象

任务页（`/pm/task`）顶部的 Segmented 切三个视图：**列表 / 看板 / 甘特**。

**问题 1：三个视图高度不统一，看板和甘特只显示了很小的一部分。**

实测（视口 1600×900，内容区 `.ant-pro-layout-content` 高 **844px**）：

| 视图 | 视图自身高度 | 占内容区 |
| ---- | ------------ | -------- |
| 列表 | ProTable 自然高度（10 行/页）≈ 600px | ~70% |
| **看板** | 单列高 **276px** | **33%** ← 最矮 |
| 甘特 | 页面容器 690px | 82% |

⇒ 看板那一大片空白最刺眼：**列只有 276px 高，下面空着 568px**，卡片多的列会被挤成一团。

**问题 2：进页面时载入没有「载入中」，突兀。**

列表视图的数据来自 `useTaskDataset`（react-query），但 ProTable 的 `request={requestLocal}` 是**同步的本地切片** ⇒ 数据集还没回来时它立刻 resolve 一个空数组 ⇒ **ProTable 不显示 loading**，用户看到「空列表 → 数据突然冒出来」。

看板/甘特因为自己渲染 `<Spin/>`，反而有载入态 ⇒ 三种视图表现不一致。

## 要什么

1. **三个视图统一吃满内容区可用高度**（同一套高度口径），超出部分在视图**内部滚动**（页面本身不滚）。
2. **列表视图载入时显示载入中**（ProTable 的 `loading`），不要「空列表突变为有数据」。

## 验收标准

- [ ] 切三个视图，视图主体高度一致，且都吃满内容区（内容区不出现外层滚动条）
- [ ] 看板列等高、卡片多时列内滚动
- [ ] 列表表格区内部滚动（表头固定），不撑出页面
- [ ] 窗口缩放 / AI 工作台收放 ⇒ 高度跟着变（不是写死的数字）
- [ ] 列表视图进页面时能看到载入态（ProTable loading），数据到位后切换
- [ ] 现有 e2e 不破：`pm-task-gantt.spec.ts` 的「页面自己不滚」「图表高度 > 300」两条断言仍成立

## 线索（给 agent 的）

- 三个视图：`frontend/src/components/pm/task/` 下的 `TaskListView.tsx` / `TaskBoard.tsx` / `TaskGantt.tsx`，容器是 `TaskWorkspace.tsx`
- 甘特里**已经有**一套高度测量逻辑（`findScrollParent` + `measurePageHeight`）⇒ 应该**抽成共享 hook** 给三个视图共用，而不是各写一套
- 甘特的 `MIN_PAGE_HEIGHT = 320` 偏小
- 载入态：列表视图的 `requestLocal`（`TaskListView.tsx`）是同步切片 ⇒ 要么给 ProTable 传 `loading={dataset.loading}`，要么让 request 等数据集

## 影响面

- [ ] 只改 `frontend/`
- [ ] 要动 `backend/ai/` 或 AiAdmin

## 规模自评

**中**（跨三个视图 + 抽共享 hook + 动 e2e 断言）⇒ 不用写 spec，但要写短设计 + 逐条自审。
```

### #33 [agent] 合并脚本的 CI 判定要把历史失败算进去（PR 永久卡住）

- **状态**：CLOSED
- **标签**：agent-task
- **所属 milestone**：（无）
- **创建**：2026-11-13T10:23:09Z
- **关闭**：2026-11-13T10:30:59Z

```markdown
## 问题

合并脚本 `scripts/agent/merge-pr.cjs` 判断 CI 用 `gh pr view --json statusCheckRollup` ⇒ 它会把**历史**的 check run 也列进来（同名 check 出现多次）。

⇒ 实测：我故意让 `body-check` 失败一次做负向测试，之后即使修好、重新跑绿了，那个 failure 还在 rollup 里 ⇒ 脚本永远说「有 CI 失败」⇒ **PR 被永久卡住**（GitHub 自己的合并按钮只看最新那次，没这个问题）。

另外 `check-runs` API 的 `conclusion` 是**小写** `success`，而 `statusCheckRollup` 里是**大写** `SUCCESS` ⇒ 直接换 API 会把 success 全判成失败。

## 要什么

- [ ] CI 状态改走 check-runs API，**按检查名只取最新一次**
- [ ] conclusion 比较大小写不敏感
- [ ] 记进 `docs/process.md` §9 的坑表

## 验收

- [ ] 一个曾经失败过、现已重跑变绿的 PR ⇒ 脚本判定「可以合并」
- [ ] 最新一次真的失败 ⇒ 脚本仍然拦住

```

```markdown
`scripts/agent/worktree.cjs remove <名字>` 会**直接删掉工作区目录**，只要：

- 目录存在
- 工作区没有未提交改动
```
