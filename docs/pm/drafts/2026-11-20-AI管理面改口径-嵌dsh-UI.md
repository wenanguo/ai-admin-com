# 草稿 · #124 口径变更：AI 管理面改用「嵌 dsh 的 UI」

> **为什么改口径**：dsh **自带**插件市场（`dsh-plugin-market` / `plugin-package-inventory-deepseek`）、
> 技能（`dsh-skill` / `dsh-skill-filesystem` / `client-ui-skill`）、
> MCP 管理（`dsh-mcp-manager`）⇒ 原计划「我们自己造三个管理面」是**重复造轮子**。
> ⇒ 改成：**起一个 dsh web 实例，用 iframe 把它嵌进 AiAdmin 的 admin 页**。

## 一、实测结论（不是猜的，2026-11-20 实跑）

| 事实 | 怎么验的 | 结论 |
| ---- | -------- | ---- |
| dsh web 能起 | `dsh web --no-open --host 127.0.0.1 --port 8399` | ✅ 起来后打印 `http://127.0.0.1:8399/?token=…` |
| **不拦 iframe** | 带 token 请求 `/` 看响应头 | ✅ **没有** `X-Frame-Options`、**没有** CSP `frame-ancestors` |
| 有 session cookie | 响应 `set-cookie: dsh-auth-…`（HttpOnly · SameSite=Strict · `Path=/` · 30 天） | ⚠️ cookie 的 `Path` 要改写成挂载前缀 |
| 有栅栏 | 非信任 authority 访问 ⇒ API 全 403 | ⇒ 要 `--trusted-host <浏览器可见的 authority>` |
| 反代是一等公民 | 官方文档 `docs/user/guide/public-deployments.zh.md` | ✅ 明确写了 `--public-url`（公告挂载前缀）+ `--trusted-host`（放行）+ 代理要**保留 Host** / **转发 WS 升级** / **改 cookie Path** |
| 管理面真的有 | `--profile web --dump-config` | ✅ 56 个 client-ui，含 `client-ui-plugin-manager`、`client-ui-skill`、`client-ui-settings-plugins`、`client-ui-settings-plugin-inventory` |

## 二、要做的事（比原计划小很多）

### 后端（`backend/ai`）

1. **新目录 `core/adapter/dsh-admin/`**
   - `instance.ts`：起/停 **dsh web 子进程**
     - 用**独立的 profile 与 DSH_HOME**（别跟服务的 `sdk` profile 混）
     - **解析启动 URL 里的 token**（免登录要用）
     - 健康检查 + 崩溃重启（有限次数 + 退避）
   - `proxy.ts`：Express 反代路由 `/dsh-admin/*`
     - **只允许 admin**（沿用我们既有的 JWT 判定口径）
     - **剥前缀**：`/dsh-admin/x` → `/x`
     - **保留浏览器可见的 `Host`**（⚠️ 不许改写成 127.0.0.1 ⇒ 栅栏会比对）
     - **免登录**：代理侧带启动 token 请求一次 `/` ⇒ 拿到 dsh 的签名 cookie ⇒ 重放给浏览器（`Path=/` ⇒ 改写成 `Path=/dsh-admin/`）
     - **转发 WebSocket 升级**（dsh 的实时通道要用）
     - **审计**：进管理面记一条（谁、何时）
2. **配置**：`DSH_ADMIN_ENABLED` / `DSH_ADMIN_PORT`（缺省 8399）/ `DSH_ADMIN_HOME` / `DSH_ADMIN_TRUSTED_HOST`（= 我们对外的 authority）
3. **生命周期**：随服务起停（挂进 `core/app.ts`）

### 前端（`frontend`）

4. `src/pages/ai/admin/index.tsx`：一个 iframe（`src="/dsh-admin/"`）+ 路由 + 菜单（**只有 admin 看得见** ⇒ `access.ts` 的 `canAdmin`）

### 测试

5. 单测：剥前缀 · Host 保留 · cookie Path 改写 · 普通用户被拒（403）· token 交换
6. 静态 e2e：断言既有 9 个端点**一字未改**；断言**没有**自造的管理面路由（防止又长回来）

## 三、明确不做

- 不改 dsh 的 UI 源码、不动 dsh 版本（锁 `0.2.2-rc.5`）
- 不做多实例 / 多用户 dsh（管理面**共享一个实例** ⇒ 「谁改的」靠我们自己的审计层记）
- 不把 dsh 的聊天/会话搬进我们的工作台（工作台仍走既有 9 个端点）

## 四、风险（明说）

| 风险 | 处置 |
| ---- | ---- |
| dsh 是 **rc**（0.2.2-rc.5）⇒ UI 变了会连带坏 admin 页 | 锁版本 + 一条冒烟 e2e |
| iframe 里可能露出**整个** dsh（聊天 / 终端 / 会话…） | 见下面的待拍板 ① |
| 反代要处理 WS 升级 | 见下面的待拍板 ② |
| dsh 单用户 ⇒ 多个 admin 共用一个实例 | 管理面本来就只给 admin ⇒ 可接受；审计记在我们这边 |
