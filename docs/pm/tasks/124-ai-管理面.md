## 1. 为什么是 iframe（不是「用 dsh 的 API 接我们的前端」）

已拍板：**整页嵌**（不裁剪 dsh 的界面）⇒ admin 会同时看到我们的工作台与 dsh 的完整 UI。

## 2. 实测到的事实（**照着做，别重新猜**）

| 事实 | 怎么验的 |
| ---- | -------- |
| dsh web 能起 | `node <dsh>/lib/bin.js --profile web --no-open --host 127.0.0.1 --port 8399 --trusted-host <authority>` |
| 启动时会打印 | `dsh web: http://127.0.0.1:8399/?token=<32 位 token>` ⇒ **token 要解析出来**（免登录要用） |
| **不拦 iframe** | 带 token 请求 `/` ⇒ **没有** `X-Frame-Options`、**没有** CSP `frame-ancestors` |
| 认证 | 带 token 请求 `/` ⇒ `303 → ./` + `set-cookie: dsh-auth-…`（HttpOnly · SameSite=Strict · `Path=/` · Max-Age 30 天） |
| 栅栏 | 浏览器若用别的 authority 访问 ⇒ **每个 API 调用都 403** ⇒ `--trusted-host` 要点名浏览器可见的 authority |
| 官方反代要求 | dsh 仓内 `docs/user/guide/public-deployments.zh.md`：代理要**保留 Host**、**转发 WS 升级**、**改 cookie Path** |

## 3. 后端怎么做

### 3.1 `instance.ts`（起停 dsh web）

- 用**官方 `web` profile**（不裁剪界面 ⇒ 不需要自己拼 profile）；
- **独立的 `DSH_HOME`**（⚠️ 别跟服务的 `sdk` profile 混 ⇒ 配置文件、会话、插件安装目录都要分开）；
- **解析启动 token**：从子进程 stdout 里抓 `?token=…`（**只在内存里**，不落盘、不进日志）；
- **健康检查**：探 `/`（拿到 401 也算「活着」⇒ 401 说明服务在、只是没带凭据）；
- **崩溃重启**：有限次数 + 退避；重启后**重新解析 token**；
- 生命周期：服务起 ⇒ 起 dsh；服务停 ⇒ 停 dsh（挂进 `core/app.ts`）。

### 3.2 `proxy.ts`（反代）

⚠️ **依赖版本**：`http-proxy-middleware@4`（v4 的底座是 **httpxy**，不是 v3 的 http-proxy ⇒ **API 变了**）：

- `pathRewrite`（v4 仍支持）· `cookiePathRewrite`（**httpxy 原生**）· `ws` · `changeOrigin`（**缺省 false = 保留 Host** ✓）
- 钩子挂在 **`on: { proxyReq, proxyRes }`**（不是 v3 的 `onProxyRes`）

**推荐配方**（Express 侧用 `app.use('/dsh-admin', proxy)` ⇒ Express 会**先剥掉前缀** ⇒ 代理收到的路径已是 `/…`）：

```ts
import { createProxyMiddleware } from 'http-proxy-middleware'

const proxy = createProxyMiddleware({
  target: `http://127.0.0.1:${port}`,
  changeOrigin: false,        // ⚠️ 保留浏览器可见的 Host（栅栏会比对）
  ws: true,                   // dsh 的实时通道
  cookiePathRewrite: '/dsh-admin/',   // dsh 发的 Path=/ ⇒ 改成挂载前缀
  on: {
    proxyReq: (proxyReq, req) => { /* ⚠️ 注入 dsh 的签名 cookie（见下） */ },
    proxyRes: (proxyRes) => { /* 抓 set-cookie ⇒ 存起来给浏览器 */ },
  },
})
```

| 要求 | 怎么做 |
| ---- | ------ |
| **只允许 admin** | ⚠️ **问权威系统**（AiAdmin）：`GET /system/user/current/info` ⇒ 判 `is_superuser === true`（**真后端的字段名**；`access === 'admin'` 只是 mock 的形状）⇒ 普通用户 **403**（**在进代理之前拦**）。⚠️ **不许解 JWT 载荷**（没验签 ⇒ 伪造 `{"access":"admin"}` 就能提权）⇒ **没注入判定器就拒绝**（fail closed） |
| **剥前缀** | 优先用 `app.use('/dsh-admin', proxy)`（Express 自己剥）⇒ 代理里**不用**再改路径；若必须用 `pathRewrite` ⇒ 只去前缀、其余原样 |
| **保留 Host** | ⚠️ `changeOrigin` **保持 `false`**（缺省就是保留）⇒ 改写成 127.0.0.1 会被 dsh 的栅栏拒 |
| **免登录** | 代理侧缓存一份 dsh 的签名 cookie（用启动 token 换来的）⇒ 在 `on.proxyReq` 里**追加**到 `Cookie` 头 ⇒ 浏览器完全不用知道 token |
| **cookie Path 改写** | `cookiePathRewrite: '/dsh-admin/'`（原生支持） |
| **WebSocket** | ⚠️ `ws: true` |
| **审计** | 进管理面记一条（谁、何时）⇒ 沿用 `core/audit/` 的语义 |

⚠️ **token 与 cookie 都只在内存里** ⇒ 不落盘、不进日志（照 `core/audit/audit-redact.ts` 的口径）。

### 3.3 配置（环境变量）

| 变量 | 缺省 | 干什么 |
| ---- | ---- | ---- |
| `DSH_ADMIN_ENABLED` | `0` | 总开关（缺省关 ⇒ 不配就不起 dsh web） |
| `DSH_ADMIN_PORT` | `8399` | dsh web 监听端口（**只绑 loopback**） |
| `DSH_ADMIN_HOME` | `<服务数据目录>/dsh-admin` | dsh 的 home（⚠️ **必须在可写目录** ⇒ 容器里要挂卷） |
| `DSH_ADMIN_TRUSTED_HOST` | 我们对外的 authority | `--trusted-host` 的值（⚠️ **必须等于浏览器看到的 host[:port]** ⇒ 否则 API 全 403） |

## 4. 前端怎么做

- `src/pages/ai/admin/index.tsx`：一个 `<iframe src="/dsh-admin/" />`（**整页嵌** ⇒ 不做尺寸裁剪逻辑，但要处理 iframe 的高度自适应）；
- 路由 + 菜单项「AI 管理」；

## 5. 测试

**单测**（`backend/ai`）：

- 剥前缀：`/dsh-admin/foo` → `/foo`；
- **Host 保留**：转发出去的 `Host` 不是 `127.0.0.1`；
- cookie Path 改写：`Path=/` → `Path=/dsh-admin/`；
- **普通用户被拒**：403；
- token 交换：拿到 `dsh-auth-…` 并注入转发请求；
- ⚠️ **伪造 `access=admin` / `is_superuser=true` 的载荷 ⇒ 被拒**（头 / cookie / 查询参数三条路）；
- ⚠️ **没注入判定器 ⇒ 503**（fail closed）；**判定器报错 ⇒ 502/401**（都不放行）。

**静态 e2e**（`scripts/e2e/`）：

- 既有 **9 个端点一字未改**（`core/routes/contract.ts` 逐条比对）；
- **没有自造的管理面路由**（防「又长回来」：不许出现 `agents` / `skills` / `mcp-servers` 这类 CRUD 路由）；
- 配置项齐了（4 个环境变量都有文档与缺省）；
- ⚠️ **admin 判定不许解 JWT 载荷**（反代里没有解载荷的代码 / 没有兜底判定 / 入口侧真的注入了判定器）。
