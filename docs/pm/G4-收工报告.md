## 三、过程中**纠正的三处判断**（都记在案）

1. **「自己写才安全」是错的** —— dsh 自带技能/MCP/插件/市场/凭据管理 ⇒ 我们又造了一遍 ⇒ **减法**（#153）。
2. **「管理面自己造」也是错的** —— dsh 的 web profile 自带 56 个 client-ui（含插件市场/技能/MCP 设置）⇒ 改成 **iframe 嵌 dsh 的 UI**（#124 口径变更）。
3. **「派活只读不写是任务描述问题」也是错的** —— 是**模型**：`MiniMax-M3.1-Flash` 连派三轮、100+ 次工具调用、**零文件写入**；换 `MiniMax-M3` ⇒ 7 分钟开写、40 分钟交 PR。

## 四、留了什么、没退什么（边界）

**没退给 dsh 的（我们的）**：闸门口径 · 审计 · 用户/权限 · 讨论上下文锚点 · 对外 9 个端点 · 会话事件流与存储（产品事实 + SSE 契约）· 每用户 MCP token（AiAdmin 的 JWT，dsh 不知道这件事）。

## 五、还没做完的（诚实记着）

1. **浏览器里人工看一眼那个 iframe**（`/ai/admin`）：本机顶不了（admin 判定要问**真 AiAdmin**）⇒ 需要真环境 + admin token。
2. **官方 DeepSeek 账户余额**：实测把额度烧完了（402）⇒ 派活已自动切回 `minimax / MiniMax-M3`；充值后删掉 `.env` 里的 `DISPATCH_PROVIDER=minimax` 即自动切回官方。

## 六、怎么继续

```bash
# AI 服务（要用真实环境：库 + AiAdmin）
cd backend/ai && npm run dev

# 管理面（默认关；要开就设这三个）
DSH_ADMIN_ENABLED=1
DSH_ADMIN_PORT=8399
DSH_ADMIN_TRUSTED_HOST=<你对外的 authority>   # ⚠️ 必须等于浏览器看到的 host[:port]
```
