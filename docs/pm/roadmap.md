### M0 · 部署（前端 + AI 服务）　`v0.9 · M0 部署（前端 + AI 服务）`（milestone #6）　**状态：已开单**

- **due**：2026-11-19（比 M1 早 ⇒ 排在最前）
- **人提的需求**：部署优先级最高；参考 AiAdmin 的 docker 部署逻辑，**区分前后端**。
- **范围**：前端静态（nginx 托管）+ AI 服务（Node 容器）；**AiAdmin 后端只连不装**（另一个仓）。
- **完成判据**：一条命令起全套；浏览器能登录、能用 AI 工作台；三条流量分对地方
  （`/` → 前端、`/api/` → AiAdmin、`/ai-api/` → AI 服务，SSE 不缓冲）。
- **人定的边界**（2026-11-13 确认时划掉四项）：
  - ❌ **不做数据库迁移** ⇒ 上线前置：`ai_*` 那 5 张表必须**已存在**于 `aipm` 库
  - ❌ **不做 HTTPS / 证书 / 443**（连 443 挂载点都不做）⇒ 只跑 HTTP 80
  - ❌ **不配 AiAdmin 侧的 MCP 白名单**（`MCP_INCLUDE_TAGS` 另议）
  - ❌ **不真机部署到任何服务器** ⇒ 只产出可部署的镜像 + 编排 + 脚本 + 文档
- **依赖**：无（**是 M1/M2/M3 的前置**）。
- **草稿**：`docs/pm/drafts/2026-11-13-部署块.md`（确认前的全文；已发布为 #38–#42）

  | issue | 候选 | 需求 | 规模 | 依赖 | 状态 |
  | ----- | ---- | ---- | ---- | ---- | ---- |
  | #38 | C1 | 前端容器化（多阶段 Dockerfile + nginx 托管静态） | 大 | 无 | 🟢 **ready** |
  | #39 | C2 | AI 服务容器化（Dockerfile + 新增 `/health` 端点） | 中 | 无 | 🟢 **ready** |
  | #40 | C3 | docker-compose 编排（前端 + AI 服务 + nginx 三条路由） | 大 | #38 #39 | ⏸ |
  | #41 | C4 | 部署脚本 `deploy.sh`（一条命令起全套 + 失败可回退） | 中 | #40 | ⏸ |
  | #42 | C5 | 部署文档 + 端到端部署验收脚本 | 中 | #41 | ⏸ |

- **五条硬约束**（写验收标准时反复用）：
  1. 容器必须监听 `0.0.0.0`（否则 nginx 502，而 healthcheck 仍显示 healthy）
  2. SSE 必须关 `proxy_buffering`（否则对话「憋很久才一次性蹦出来」）
  3. AI 服务的技能路径是 **cwd 相对** ⇒ 镜像 WORKDIR 要对
  4. `.ai/auth.json` 是凭据 ⇒ **不进镜像**
  5. `/ai-api/` 前缀不能省（会与 `/api/` 前缀匹配抢路由）
