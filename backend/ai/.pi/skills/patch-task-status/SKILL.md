# 批量改「是否可用」

工具：`mcp__aiadmin__patch_task_status`

## ⚠️ 它**不是**「改任务状态」

| 你想干的事 | 用哪个工具 |
| ---------- | ---------- |
| 改任务的**业务状态**（todo → in_progress → done） | `mcp__aiadmin__update_task`（带 `status_code`） |
| 批量**启用 / 停用**任务（`status` = 1 / 0） | `mcp__aiadmin__patch_task_status`（本技能） |

> ⚠️ 后端这个工具的**描述**写着「`status_code` 取字典值（如 todo/doing/done）」，
> **但它的参数 schema 是 `status`：整数 0/1**（=「是否可用」）⇒ **两处自相矛盾**。
> ⇒ **一律按 schema 传整数 0/1**；按描述传字典字符串 ⇒ 422。

## 参数（`mcp__aiadmin__patch_task_status`）

| 参数 | 类型 | 必填 | 说明 |
| ---- | ---- | ---- | ---- |
| `ids` | array | — | 要改的**任务 id 列表**（整数数组；一次可给多个） |
| `status` | integer | — | 是否可用：`1` = 可用，`0` = 停用（**默认是 0**） |

> ⚠️ 这个工具的 schema **没有 `required`**（两个参数都不是「必填」）
> ⇒ **但你必须两个都显式传**：
> - `ids` 漏了 ⇒ 一条都改不到；
> - `status` 漏了 ⇒ 用它的默认值 **0 = 停用** ⇒ 把这批任务全停用了。

## 流程

1. **确认要改哪几条**：用户说的可能是标题而不是 id
   ⇒ 先用 `mcp__aiadmin__list_tasks` 找到对应的 id，**再**批量改。
2. **批量改**：调用 `mcp__aiadmin__patch_task_status`，一次把 id 都放进 `ids`。
   - ⚠️ **`status` 一定要显式传**（它的默认值是 `0` = 停用）
     ⇒ 忘了传就把这批任务全停用了。
3. **为什么用它而不是逐条 `update_task`**：
   - `update_task` 是**全量 PUT** ⇒ 逐条改要先把每条任务的完整字段拉出来再整体提交
     ⇒ 字段漏一个就 422 ⇒ 批量场景极易出错；
   - `patch_task_status` **只改这一个字段** ⇒ 批量场景**更安全**。
   - ⚠️ 但它**改不了业务状态**（见上面那张表）⇒ 业务状态流转仍走 `update_task`。
4. ⚠️ **改数据要等人点头**：本服务有「待确认」闸门（`patch_` 开头的工具会被挂起）
   ⇒ 把要改的值填对，等用户在「待确认」里点头。
5. **回报**：说清「哪几条（标题）被改成了什么」（停用 / 恢复可用）。
